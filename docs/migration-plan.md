# План миграции DentPilot на React + Tauri

Основан на `docs/migration-audit.md`. База отсчёта — `docs/current-functionality.md`.

⭐ **Главное решение плана.** Задание предлагает порядок «React → Tauri →
обновления → CI». Аудит показал, что этот порядок ставит три блокера на первый
же шаг (origin, кука, CSRF-гейт) и лишает права на ошибку в обновлениях.
Порядок здесь **обратный по первым двум шагам**: сначала API и React **внутри
нынешнего сервера**, окно Tauri — предпоследним шагом. Цель та же, риск
несопоставим.

---

## Правила, действующие на всех этапах

⛔ **Печатные документы остаются серверными навсегда.** 043/e, acord,
plan-acord, пародонтограмма, анамнеза, касса, лист восстановления. У каждого
свой `<!doctype>` и свой инлайновый CSS — они печатаются, даже если бандл не
загрузился. Приказ МЗ 828/2011, подпись на бумаге, хранение 5 лет.

⛔ **Экраны аварии остаются серверными:** вход, установка PIN, восстановление,
`CONFIG_BROKEN`, обновление, перезапуск. Экран, который обязан открыться, когда
бандл не поднялся, не может жить в бандле.

⛔ **Origin не меняется.** Фронтенд отдаёт тот же FastAPI по
`http://127.0.0.1:<порт>`. Это снимает блокеры 3, 4 и половину 5 из аудита
и оставляет `core/auth.py` нетронутым.

⛔ **`db.py` и `engine.py` миграция интерфейса не трогает.**

⭐ **Экран не считается перенесённым, пока его проверки не переписаны.**
Зелёный прогон, потерявший половину смысла, хуже красного.

## Этап 0 — до единой строки кода

| Шаг | Проверяется |
|---|---|
| Ответы Олега на 6 открытых вопросов аудита | без п.1 и п.2 порядок работ неопределён |
| Решить, где живут `docs/` (репозиторий публичный) | `git status` чист, `.\dev check` зелёный |
| Карта «экран → сюиты → число проверок» для 41 экрана | таблица в `docs/screen-test-map.md` |

⚠️ Замер данных нужен не «для порядка»: `_pl_rows` грузит **всех** пациентов
шестью запросами и фильтрует в Python, статистика тянет в память два периода до
366 дней, одонтограмма отдаёт **обе дуги** (до 104 SVG). В React список
пациентов будет дёргаться на каждую букву.

## Этап 1 — CI **до всякого Tauri**

Заводится сейчас, на существующем Python-стеке. Репозиторий публичный → минуты
Actions не тарифицируются, а 1810 проверок сегодня не гоняются **нигде, кроме
машины Олега**.

```yaml
# .github/workflows/test.yml — на каждый push и PR
python tests/run_tests.py          # 1810 проверок, ~6 минут
```

⛔ Только тесты. Ни сборки, ни релиза, ни секретов. `GITHUB_TOKEN` не нужен.

**Готово, когда:** зелёная галочка на коммите в `main`, и красная — на
намеренно сломанном.

## Этап 2 — JSON API рядом с HTML

Ничего не удаляется. Появляется префикс `/api/*`.

1. **`api_guard` / `api_require`** — отдельная пара, отдающая `401`/`403` JSON.
   ⛔ 53 вызова `_guard` и 41 вызов `require` на HTML-маршрутах **не трогать**.
2. **Конверт ответа** `{ok, code, field?, data?}` с **теми же 90 кодами**
   `MSG_BANNER`. Новых кодов не изобретать.
   `200` ok · `422` валидация · `409` конфликт · `403` нет прав · `401` не вошёл.
3. **Разбор `GET /admin/patient/{pid}`** — 909 строк, 15 обращений к базе,
   расчёты внутри f-строк. Минимум на 8 эндпоинтов. ⭐ Эти арифметики сегодня
   не покрыты тестом отдельно — только через готовую страницу; при разборе они
   впервые получают собственные проверки.
4. **Намерение — явным полем.** ⛔ Не полагаться на `undefined` против `""`:
   запрос несёт `shown: ["sf","mk","state"]` — что именно экран показывал.
   Иначе повторяется потеря данных 08-16.

**Готово, когда:** `POST` того же тела дважды подряд даёт **тождественную**
строку `teeth` в базе; `curl` без куки на любой `/api/*` даёт `401` и
`application/json`.

## Этап 3 — каркас React внутри нынешней рамки

```
frontend/
  src/{app,components,features,hooks,services,stores,types,utils}/
  package.json  tsconfig.json  vite.config.ts
```

⭐ **Оболочка НЕ дублируется в React.** Сайдбар, топбар, тема, шрифты, класс
`anim`, PWA-шапка остаются серверными. `_shell` на мигрированном экране отдаёт
`<div id="root" data-screen="...">` и `<script type="module">`.

⚠️ **Имена файлов сборки фиксируются:** маршрут `/static/{kind}/{name}`
принимает только маску `[a-z0-9_-]+\.js` — хешированные имена Vite вида
`index-D4f2Ab9c.js` получат **404**. В `vite.config.ts`:
`entryFileNames: 'bundle.js'`, `assetFileNames: 'bundle.css'`; версионирование
берёт уже существующий `?v=` из `layout._asset_ver()`.

⚠️ **Иконки генерируются, не копируются:** `icons.ts` с union-типом `IconName`
собирается скриптом из `layout._I` (76 иконок, 357 вызовов `_ic`).

⛔ **Ничего графического от Windows** — правило карты действует и в `.tsx`.

**Готово, когда:** один пустой экран смонтирован, `npm run build` кладёт
`bundle.js`, `Build-Desktop.ps1` возит его в exe, дымовой тест зелёный.

## Этап 4 — первый экран

Кандидат — **`/admin/settings/clinic`**: 9 949 байт, форма без живого опроса,
без печати, без перетаскивания.

⛔ **Журнал дня переносится ПОСЛЕДНИМ.** Правило: на странице одновременно
не существуют `#root` и `#live`, иначе `panel.js` через 12 секунд подменит
`innerHTML` под смонтированным деревом и всё умрёт молча.

**Готово, когда:** экран работает, его сюиты переписаны на JSON, число проверок
не уменьшилось.

## Этап 5 — остальные экраны, по одному

Порядок от простого к хрупкому. Самое хрупкое — в конце:

1. настройки (11 секций), врачи, статистика, касса;
2. поиск и список пациентов;
3. фиша пациента (после разбора на 8 эндпоинтов);
4. **скобка моста** — `BRIDGE_DRAW_JS` мерит `offsetLeft/Top/Width` кнопок
   зубов, правит на инлайновую `--arc`, резервирует место классом `.br-room`
   **до** замеров. Самый хрупкий кусок интерфейса;
5. **ввод пародонтограммы** — автопереход к следующей точке, клавиша `b`,
   пересчёт BOP% тем же счётом, что на сервере;
6. **детальная одонтограмма**;
7. **журнал дня** — в том же коммите убрать его ключ из `LIVE_RELOAD`.

⚠️ Живой журнал в React строится **поверх данных, а не разметки**. Заодно
снимается ограничение «body детерминирован»: линию «сейчас» пришлось унести
в браузер только потому, что md5 берётся от HTML.

## Этап 6 — сторожа

Переписываются **одним заходом**: `test_structure.py` (6 правил разбирают
литералы `.py`), `mutate.py` (сверяет списки в обе стороны — **упадёт сам**),
`test_guards.py` (8 из 12 проверок), `smoke_exe.py` (~10 из 31 привязаны
к `panel.css`/`panel.js`/`fonts.css`).

⭐ Новое правило = проверка в `test_structure.py` + мутация в `mutate.py`.
⛔ Список, который **включает** требование, обязан проверять, что имена в коде
ещё существуют, — иначе он позеленеет навсегда.

## Этап 7 — окно Tauri

Только теперь. К этому моменту продукт уже работает на React, и Tauri меняет
**339 строк `desktop.py`**, а не всё приложение.

| Было | Стало |
|---|---|
| `webview.create_window(1280×860, confirm_close)` | `WebviewWindowBuilder` + `CloseRequested` + `prevent_close()` |
| 4× `ctypes.MessageBoxW` | `tauri-plugin-dialog` |
| `ALLOW_DOWNLOADS=True` | `on_download` (10 `FileResponse` + 4 `Content-Disposition`) |
| `/health` + EXCLUSIVE-бинд | ⚠️ `single-instance` **фокусирует** окно, а сегодня второй клик открывает **второе** окно. Смена поведения — решать явно |

⛔ **Sidecar всегда наследует токен интерактивного пользователя.** Служба
Windows или LocalSystem делают `db.key` нечитаемым у каждой клиники
с шифрованием.

⛔ **PyInstaller `--onefile` → `--onedir`.** У onefile бутстрэппер порождает
настоящий процесс; `CommandChild::kill()` на Windows — это `TerminateProcess`,
он **не убивает внуков**. Нужны три страховки: onedir, Job Object
с `KILL_ON_JOB_CLOSE`, и поток-сторож в Python на исчезновение родительского PID.

⛔ **Не перезапускать сайдкар**, когда на диске лежит `data\db-key.pending`
или `data\db-decrypt.request`: переезд базы делает лаунчер до открытия
соединения, и рестарт посреди него — порча с отложенным проявлением.

⚠️ `data\dentpilot.log` **без ротации** — цикл перезапусков будет растить его
неограниченно. Ротацию добавить здесь же.

⚠️ Правило брандмауэра (`lan.py`) заводится на `sys.executable`, который при
sidecar — **сайдкар**, а не то, что видит клиника.

## Этап 8 — упаковка

⭐ **`tauri build --bundles none` + существующий Inno Setup.** Тогда переживают
все **152 строки Pascal-логики** в `DentPilot.iss`: запрет Program Files,
проба записи, папка `C:\Users\Public`, две ветки WebView2, окно «данные клиники
остались», фиксированный AppId, румынский мастер.

⛔ Отказ от Inno в пользу NSIS — **отдельное осознанное решение**, а не
«у Tauri так принято». Штатный NSIS ставит per-user в `%LOCALAPPDATA%`
(две смены = две учётки = пустой журнал) и при обновлении запускает
деинсталлятор, который чистит папку установки — **вместе с картотекой**.

**Приёмочная проверка, обязательная:** на пустой машине поставить версию N,
завести пациента, поставить N+1 **поверх**, убедиться, что пациент на месте.

## Этап 9 — обновления

⛔ **Tauri Updater не включать.** Причины в аудите: закрывает путь назад,
требует вечный приватный ключ, не умеет каналов, ставит инсталлятором вместо
подмены файла.

⭐ **Переход бесплатен, если соблюсти контракт ассета.** Нынешний апдейтер
бандлер-агностичен: имя точно `DentPilot.exe`, размер, sha256 — и bat подменит
что угодно. Установленные клиники переедут **старым механизмом**.

⚠️ **Проверить экспериментом, а не предположением:** собрать Tauri-заготовку,
положить её вместо `dist/DentPilot.exe`, руками выполнить те же три команды
`move`/`move`/`start` и убедиться, что она поднимается и отвечает на своём порту.

Что править в тот же коммит: `release.py:141` и гейты `:191-193`, `:226-232`
(«ровно два ассета, единственный `.exe` называется `DentPilot.exe`») и
`check_release.py:143-151`.

⚠️ Переходный релиз выпускать так, чтобы у ассета **был** `digest` — то есть
через API GitHub, а не веб-путём, где sha256 молча пропускается.

⚠️ Прогнать новый клиент на **всех** базах-образцах из `test_migrate.py`
(v0, v2, v3, v4, база от выпущенной 1.20.0) — это готовый приёмочный лист.
Плюс `check_slot_guard.py`: любая миграция трогает `db.py`.

⚠️ Проверить обновление **на ноутбуке от батареи**: у задачи `schtasks`
`DisallowStartIfOnBatteries=true` по умолчанию, и снять её ключом нельзя.
Ни один тест этого не видит.

## Этап 10 — выпуск

Лестница не меняется: **push → сборка → pre-release → канарейка → publish**.

⛔ CI доводит до **pre-release и ни на шаг дальше**. Publish — команда с машины
Олега, по его слову, на каждый выпуск.
⛔ `GITHUB_TOKEN` с `contents: write`, живущий минуты. **`DENTART_UPDATE_TOKEN`
в Actions не класть вообще** — это прямой канал «обновление в один клик» во все
клиники.
⛔ Тег — поимённо, никогда `--tags`.
⛔ Сторонние actions пинить по SHA коммита, а не по тегу.
⛔ Без зелёного дымового теста нет ни артефакта, ни pre-release.

**Синхронизация версии.** Источник один — `engine.py:22`. Появляются
`package.json`, `tauri.conf.json`, `Cargo.toml`, тег, имя ассета, запись
в реестре. `scripts/sync_version.py --check` зовётся в трёх местах:
`dev check`, первый шаг workflow, отдельное правило в `test_structure.py`.
⚠️ Разъехавшаяся версия = **вечный цикл обновления** у клиники.

## Чего в плане нет намеренно

- **Linux и macOS.** Продукт продаётся клиникам в Молдове на Windows.
  Платформы не добавляются искусственно.
- **Переписывание бэкенда на Rust.** 23 635 строк, из них `db.py` 3 518 при 109
  async-функциях с двумя текстами SQL. Логика работает и проверена 1810 тестами.
- **Менеджер состояния сверх TanStack Query + React Context.** 41 экран,
  состояние в основном серверное. Библиотека добавляется, когда появится
  причина, а не заранее.
- **Пересъёмка витрины и правка README** — это работа, но она делается **после**
  того, как интерфейс устоялся, и стоит отдельной строкой.

## Точка возврата

На этапах 0–6 продукт **остаётся прежним exe**: React живёт внутри него,
обновления не тронуты, откат — обычный `git revert`.

Необратимость начинается на **этапе 7**, когда `.old.exe` у клиники впервые
окажется Python-сборкой, а рабочий exe — Tauri. ⭐ До этого шага копия папки
установки пилота обязана лежать офлайн.
