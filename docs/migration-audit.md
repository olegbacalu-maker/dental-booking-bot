# Аудит DentPilot перед миграцией на React + Tauri

Снято **16.09.2026** с `v1.26.0-2-gc6ed5cf`. Код НЕ менялся: аудит только читал,
плюс один прогон тестов и одна песочница на порту 8099.

## Как снято

17 агентов в три волны: 12 читателей по подсистемам (784 факта со ссылками
`файл:строка`), 4 аналитика осуществимости, 1 критик полноты. Сверх этого —

# 3. Механизм обновления — разобран по пунктам

Это самая зрелая часть продукта. 713 строк, из которых ~550 — выученная
машинерия Windows, а не «скачать файл».

| № | Вопрос | Ответ (проверено в коде) |
|---|---|---|
| 1 | Откуда узнаёт о новой версии | Четыре источника: `api.github.com/repos/{REPO}/releases/latest`, GraphQL (черновики), `/releases?per_page=100`, и **веб-фолбэк без API** — `releases.atom` + HEAD |
| 2 | Какой репозиторий | `bot/app/repo.py:16`, одна константа. Репозиторий **обязан быть публичным** — у приватного анонимный `/releases/latest` даёт 404 |
| 3 | GitHub Releases | Да. Выбор по каналу; при равной версии предпочитается запись **с файлом** |
| 4 | Токен | Только у разработчика, из окружения. Клиникам не нужен. Черновики без токена не видны никому |
| 5 | Каналы | `stable` / `beta` / `draft`. Beta **без секрета** — переключатель `DENTART_CHANNEL` в `dental.env` |
| 6 | Сравнение версий | `_ver()` — кортеж из трёх чисел с добивкой нулями. ⚠️ Без добивки тег `v1.10` дал бы `(1,10) < (1,10,0)` и релиз стал бы невидим **всем клиникам разом** |
| 7 | Что качается | Ассет, чьё имя **точно равно** `dentpilot.exe` (или историческое `dentart.exe`). ⛔ Не «первый .exe»: GitHub сортирует по имени, и `DentPilot-Setup-*.exe` встаёт раньше (`-`=0x2D < `.`=0x2E) — отбор по порядку скачал бы **установщик** и затёр им работающую программу |
| 8 | **Контрольная сумма** | **Да**: порог 5 МБ + точное равенство `asset_size` + **sha256** из поля `digest`. ⚠️ На веб-фолбэке digest неизвестен и sha256 **пропускается** |
| 8b | **Цифровая подпись** | **Нет никакой.** Ни Authenticode, ни minisign. `codesign_identity=None` в spec |
| 9 | Запуск установки | Установщик **не запускается**. bat-скрипт: рабочий exe → `.old.exe`, новый → на его место |
| 10 | Автоперезапуск | Да, через `schtasks`. ⚠️ Ноль от schtasks — не доказательство: скрипт создаёт файл-метку `.run`, программа ждёт её до 10 с и только тогда гасится |
| 11 | Ошибки | Сеть/403 → фолбэк на веб-путь, иначе баннер. Битый файл → отказ до подмены. bat упал → ветки `:restore`/`:fail` возвращают старый exe и запускают его |
| 12 | Откат | Есть: `.old.exe` рядом. Удаляется только в `startup` **после того, как база открылась** |
| 13 | Фоновая проверка | При старте + каждые 6 ч; 300 с, если версия объявлена, а ассета ещё нет |
| 14 | Лимиты API | Учтены. Анонимный лимит 60/час **на адрес**, а клиника сидит за провайдерским NAT — ради этого и написан веб-фолбэк |

⭐ **Увидено живьём в этой сессии.** При запуске песочницы GitHub API ответил
`HTTP Error 403: rate limit exceeded`, программа ушла на `releases.atom`,
определила `v1.26.0` и продолжила работать. Требование задания §14
(«GitHub недоступен → не ломать приложение») **уже выполнено** — его надо не
построить, а не потерять.

## ⭐ Главный вывод аудита по обновлениям

**Нынешний апдейтер бандлер-агностичен.** Он не проверяет, что скачанный файл —
PyInstaller-сборка. Он проверяет имя, размер и sha256, после чего подменяет файл.

Отсюда: **если Tauri-версия собрана одним самодостаточным exe с именем
`DentPilot.exe`, читающим данные из своей же папки, — установленные клиники
переедут на неё СТАРЫМ механизмом.** Без переходного релиза, без единой новой
строки на их стороне.

И обратное следствие: **Tauri Updater закрывает путь назад.** Он ставит
обновление запуском инсталлятора и требует minisign-подпись. После первой такой
установки клиент больше не примет PyInstaller-exe, а правило проекта «релизы
только вперёд, `latest` не перевешивается» означает, что чинить плохую
Tauri-сборку можно только следующей Tauri-сборкой.

⛔ Плюс появляется **приватный ключ, потеря которого мёртво отключает обновления
у всех установленных машин навсегда**: публичный ключ вкомпилирован в бинарник,
переподписать его удалённо нечем — единственный канал доставки и есть тот самый
апдейтер, который теперь отвергает неподписанное.

# 4. Данные — что нельзя потерять

Всё живёт **рядом с exe** и переживает обновление по замыслу:

```
C:\Users\Public\DentPilot\
  DentPilot.exe
  clinic.json          профиль клиники: врачи, услуги, часы, seq, тема
  dental.env           TELEGRAM_TOKEN, ADMIN_KEY, DENTART_PORT, DENTART_CHANNEL,
                       DENTART_LAN
  data\
    dental.db          картотека; МОЖЕТ быть под SQLCipher
    db.key             ключ базы под DPAPI
    auth.json          PIN и учётки (PBKDF2)
    files\             снимки и документы пациентов
    backups\           14 копий, ротация
    dentpilot.log      WARNING, без ротации
```

⛔ **DPAPI привязан к учётке Windows.** Переустановка системы, другой ПК или
работа под другой учёткой делают `db.key` нечитаемым **навсегда**. Единственное,
что спасает, — печатный лист восстановления.

⛔ **Картотека может быть зашифрована**, и штатный `sqlite3` её не откроет.
Любое соединение мимо `db.py` ломается у клиники, включившей шифрование.

# 5. Доступ — и почему он не переживёт переезд origin

- Вход по **одному паролю**, логин необязателен (регистратура набирает его
  десятки раз в день). Пароли обязаны быть уникальными.
- Кука `admin_auth` = `uid.role.sid.подпись`, **`httponly`, `samesite=lax`,
  без `secure`**, срок 30 дней.
- `PERMS` — одна таблица: director (деньги, настройки, учётки, врачи),
  receptie (врачи), medic (ничего сверх пациентов и записей).
- Роль читается **из файла по id**, а не из куки: понижение действует сразу.
- `same_origin_post()` сверяет `netloc` заголовка `Origin` с `Host`.
- Сигнализация подмены `auth.json`: sha256 в `schema_meta`.

⛔ **Блокер для Tauri.** Tauri v2 грузит фронтенд с `http://tauri.localhost`.
Тогда:
1. `same_origin_post` вернёт `False` → `/admin/login`, `/admin/setup`,
   `/admin/recover` ответят **403 ещё до ввода пароля**;
2. кука с `samesite=lax` на cross-site fetch **не уйдёт** → `current_user`
   увидит пусто → `_guard` будет вечно редиректить на вход.

Клиника увидит: **«программа не пускает, пароль не подходит».**

⭐ **Обход, который снимает весь класс проблемы:** отдавать `index.html` React
тем же FastAPI и открывать окно Tauri на `http://127.0.0.1:<порт>/`. Тогда
origin совпадает с Host, `core/auth.py` не трогается **ни одной строкой**, LAN и
телефон врача продолжают работать.

## Правила выпуска, которые ломает наивный CI

⛔ Тег отправлять **поимённо** (`git push origin v1.26.0`), а не `--tags`:
у репозитория лежат старые локальные теги **без «v»**, и `--tags` утаскивает их
на origin заодно — 17.08 так уехал тег `1.13.0` на чужой коммит.

⛔ Сборка идёт **до** тега, намеренно. Триггер `on: push: tags` меняет порядок
на обратный, и упавшая сборка оставляет висящий тег.

⛔ **Publish только по слову Олега.** CI имеет право доводить дело до
pre-release и ни на шаг дальше.

# 8. Что аудит сначала наврал

Критик проверил ключевые утверждения в коде. Семь не подтвердились; три из них
меняли бы решения:

1. **«JSON-эндпоинтов нет вообще»** — их 13 в двух файлах. Сводка противоречила
   сама себе: соседний раздел их же и называл.
2. **«Единственный `fetch` — опрос живого журнала»** — их шесть. На заниженном
   числе строился вывод «весь фронтенд ходит только same-origin».
3. **«`smoke_exe.py` — единственная проверка собранного бинарника»** — ворот
   двое, и второй (`check_slot_guard.py`) закрывает самый дорогой класс отказа.
4. Расширений в `_OPEN_EXT` — 26, а не 24.
5. Состав выгрузки по закону 195 — 12 разделов, а не 13 и не 11. ⚠️ Расхождение
   означает, что паритет «выгрузка = удаление» никто фактически не сверял.
6. Гейт `is_desktop()` живёт **внутри** `update.py:121`, а не в `main.py` —
   вывод верен, но по этому описанию гейт искали бы не там.
7. Доля «42 % проверок читают HTML» посчитана делением статики на статику.

⭐ Прайор отсюда: **веер агентов уверенно противоречит сам себе, если его не
сводить.** Отдельный критик с правом лезть в код окупился.

# 10. Открытые вопросы — на них отвечает Олег, не код

1. **Tauri ради чего?** В прочитанных материалах нет ни одной жалобы клиники
   или пилота, которую React закрывает. Пять просьб пилота (два рабочих места,
   невидимая ошибка записи, телефон, поиск, мигание) закрыты **без него**.
   По прайору проекта «у кандидата два триггера» это надо назвать вслух:
   рабочего триггера сейчас нет, есть инженерный.
2. **Замораживаем ли выпуск функций на время перехода?** С 01.08 в `bot/` ушло
   262 коммита; `engine.py` тронут в 104, `layout.py` в 57, `main.py` в 54,
   `db.py` в 43, `panel.css` в 42, три `routes.py` по 31. Длинная ветка
   столкнётся ровно с этими файлами, а в памяти проекта уже записана грабля:
   **база диффа обязана быть неподвижной.**
3. **Облако размораживается или выкидывается?** Если мертво — половина `db.py`
   (второй текст SQL в каждой из 109 функций) выбрасывается и оценка падает
   вдвое. `Dockerfile` не менялся с 30.07, `docker-compose.yml` с 31.07.
4. **Где живут эти документы?** `app/` — **публичный репозиторий** (проверено:
   `HTTP 200` анонимно), и это требование автообновления. Внутренние заметки
   проекта живут в тонком репозитории `D:\DentProject`. Пока файлы лежат
   в `app/docs/` и **не запушены**; ⚠️ они делают дерево грязным, а
   `Build-Installer.ps1` отказывается собирать на грязном дереве.
5. **Скриншоты и README.** 678 строк README и 8 скриншотов витрины становятся
   ложью в день выпуска нового интерфейса. Это отдельная работа, не попавшая
   ни в одну оценку.
6. **`examples/clinic-zambet/clinic.json`** — третья копия схемы профиля
   клиники, на которую нет ни одной ссылки в репозитории. Эталон или мусор?

# 11. Вердикт по слоям

| Слой | Вердикт | Трудоёмкость |
|---|---|---|
| Интерфейс → React | Осуществимо, **только островами** экран за экраном | очень много |
| Python под Tauri | Осуществимо **только как sidecar**; Rust-переписывание — плохая идея (23 635 строк) | очень много |
| Обновления | Осуществимо, но **свой механизм лучше Tauri Updater** | много |
| Сборка и CI | Не перенос, а постройка заново + новый постоянный секрет | много |

⭐ **Рекомендация аудита, если коротко:** порядок работ обратный тому, что
просит задание. Сначала **JSON API рядом с существующими HTML-маршрутами** и
React **внутри нынешнего сервера** на `http://127.0.0.1:<порт>`. Тогда origin
совпадает, `auth.py` не трогается, печать и обновление не трогаются, LAN
работает. Окно Tauri после этого — замена pywebview **одним шагом**, а не
условием всей работы.

План по этапам — `docs/migration-plan.md`.
