# Контракт B1: React забирает оболочку

Что закрывается ДО первой строки кода. Опирается на
[shell-inventory.md](shell-inventory.md) (232 позиции) и на решение
[spa-transition.md](spa-transition.md).

Три слоя, и третий — главный: контракт обязан описывать не только то, что
появляется, но и то, чего после B1 остаться **не должно**. Иначе это «перенесли
сайдбар», а не проверяемый переход.

```
B1 Contract
├── 1. ShellModel     что React получает
├── 2. Legacy Bridge  как серверная оболочка временно сосуществует
└── 3. Negative Guard что НЕ должно остаться
```

Плюс отдельная, перпендикулярная всем трём часть — **контракт первого кадра**.

---

## 1. ShellModel — что React получает

⛔ **Это не `/api/me`.** Никакого «эндпоинта про пользователя вообще»: модель
отдаёт ровно то, что нужно оболочке, и ничего сверх. Лишнее поле здесь — это
новое знание в браузере, которое завтра начнут использовать как право.

```
ShellModel
├── identity   { name, role, initials, can: {money, settings, doctors, users} }
├── clinic     { name, logo_url }
├── runtime    { version, tz, edition, theme: {style, vars} }
├── nav        [ {key, href, label, icon, visible} ], active
├── signals    { tamper, split, slot, setup_hint }   — каждый: shown + данные
└── frame      { sub, rail, bell }
```

⭐ **Права приезжают РАЗРЕШЁННЫМИ, а не таблицей.** В модели `can.money`, а не
`PERMS`. Таблица приглашает клиента вычислять право самому; булев ответ —
не приглашает. Сервер остаётся единственным, кто знает `PERMS`.

⛔ **Скрытый пункт меню — не право.** Модель управляет ОТОБРАЖЕНИЕМ. Каждый
маршрут по-прежнему зовёт `require(...)` / `api_require(...)`, и роль
по-прежнему читается из файла по id, чтобы понижение действовало немедленно.
React-загрузка **не становится** новой границей безопасности:

```
React Shell ──► отображение
      │
      └──────► navigation ──► FastAPI ──► authoritative permission check
```

### Как модель доезжает — развилка закрыта

**Инлайном на первом кадре, обновление — эндпоинтом.**

| | Решение |
|---|---|
| первый кадр | атрибутом на узле монтирования, тем же механизмом, что `data-params` (`json.dumps` + `html.escape(quote=True)` в `react_mount`) |
| обновление | `GET /api/shell` — при смене роли, появлении сигнала, переименовании клиники |

⛔ Модель **не может** приезжать только запросом. Оболочка, которая ждёт
`fetch`, рисует пустой сайдбар на первом кадре — это ровно то мигание, ради
устранения которого B1 и делается. Сервер и так печатает страницу; напечатать
вместе с ней и модель ничего не стоит.

⚠️ Модель считается **один раз на сервере** и кормит обе оболочки — серверную и
React-овскую. Это идиома проекта (`lan.py`, `crypt.py`, `system.py`,
`stats/model.py`): правило живёт в одном месте, отрисовщиков два. Второй
вычислитель состава меню разошёлся бы с первым молча.

## 2. Legacy Bridge — как две оболочки сосуществуют

Во время B1 серверная оболочка **не удаляется**: 19 маршрутов остаются
серверными навсегда (печать 043/e, acord, plan-acord, анамнеза, касса, QR, лист
восстановления; вход, установка PIN, восстановление, экран раздвоения;
витрина бота, `/demo`, замороженный Telegram, фрагмент peek). У них своя
оболочка, и она никуда не денется.

`?ui=legacy` продолжает работать без изменений: это аварийный выход, и он
обязан отдавать **полностью** серверную страницу, включая серверный сайдбар.

### У каждой точки моста — назначенный срок жизни

| Точка | Живёт до | Как умирает |
|---|---|---|
| `#root[data-screen]`, `[data-params]` | **B2** | роутер начинает выбирать экран по адресу — ✅ 24.09 (первая половина B2): `data-screen` больше не выбирает, а СВИДЕТЕЛЬСТВУЕТ; `data-params` живёт до загрузчиков второй половины |
| `#root[data-shell]` | **остаётся** | ⭐ B4 (24.09) сделал её не мостом, а механизмом: модель едет с документом и на первом кадре, и при переходе без перезагрузки — клиент запрашивает документ нового адреса и читает тот же атрибут (`services/doc.ts`) |
| `body[data-v]` | **конца B1** | версия уезжает в `runtime.version`, читатель в `DashScreen` переписывается ТЕМ ЖЕ коммитом |
| `#sf_clock[data-tz]` | **конца B1** | пояс уезжает в `runtime.tz`, `dashFx.clinicTz()` переписывается ТЕМ ЖЕ коммитом |
| `html.anim` | **остаётся** | это решение о первом кадре, оно обязано приниматься ДО React |

⛔ Строки «уезжает в модель» и «читатель переписан» обязаны быть в ОДНОМ
коммите. Разнесённые, они дают окно, в котором React читает атрибут, которого
уже нет, и получает `undefined` вместо версии — без ошибки на экране.

## 3. Negative Guard — чего после B1 быть не должно

Каждый пункт — проверяемое утверждение, а не пожелание.

| # | Не должно остаться | Чем проверяется |
|---|---|---|
| 1 | React-страница зависит от серверного `<h1>` и `.sub` | в ответе React-маршрута нет серверных `.content > h1` и `.content > .sub` |
| 2 | сайдбар считается `_shell` на React-ветке | `_sidebar` не вызывается на React-ветке (разбор `ast` мест вызова) |
| 3 | системный сигнал существует только как HTML | множество полей `signals` в модели == множеству функций-баннеров |
| 4 | новая сетка держится на `display:contents` | правила `#root,.dp-react-root{display:contents}` в `panel.css` больше нет |
| 5 | точка моста без срока | у каждой точки в таблице §2 назван этап смерти, и имена ещё существуют в коде |

⚠️ Пункты 2, 3 и 5 — списки с **включающей полярностью**: правило ищет ИМЕНА и
позеленеет навсегда, если имя переименуют. По прайору карты каждому нужен
ЯКОРЬ («имена в коде ещё есть») плюс строка в `mutate.py`.

⛔ **Пункт «навигация не требует перезагрузки» в B1 НЕ проверяется** — это B4.
Внести его сюда значит потребовать от B1 того, чего он по определению не
делает, и получить красный сторож на правильном коде.

## 4. Контракт первого кадра

⭐ Единственная часть, у которой есть **измеримая** цель, а не только паритет.

Причина мигания измерена соседней сессией покадрово: полная загрузка документа →
первый кадр показывает серверную заглушку 20–80 мс → разбор 452 КБ → данные
вторым кругом → документ 808→1199 px → появляется полоса → всё правоприжатое
едет на 15 px. Инвентарь добавил к этому место: `bundle.css` и `bundle.js`
печатает `react_mount` **внутри `.content`**, после заголовка и четырёх
баннеров, и в документе нет ни `preload`, ни `<base>`, ни `<noscript>`.

**Что измеряется** (одни и те же данные, одно и то же окно, CDP):

1. момент появления оболочки (сайдбар, шапка) на кадре;
2. момент появления содержимого экрана;
3. число сдвигов раскладки и суммарный горизонтальный сдвиг;
4. высота документа в начале и в конце;
5. момент начала загрузки `bundle.js`.

⛔ **Базовая линия СКОРОПОРТЯЩАЯСЯ.** «До» существует ровно до первого коммита
B1. Снять её надо ДО того, как что-либо в оболочке тронуто, иначе часть 4
превращается в обещание.

⛔ И отрицательная половина, по прайору о ложном красном стенде: стенд обязан
показать пару. Недостаточно, чтобы после B1 было зелено — нужно, чтобы на
сегодняшнем коде те же измерения давали ХУДШИЕ числа. Иначе стенд не доказывает
ничего.

## Развилка live: чего ждали и что оказалось

Живые поверхности (`/admin`, `/admin/week`, `/admin/all`, `/admin/doctor/{dk}`)
оставлялись последними намеренно: там ждали не очередного поля модели, а
изменения владения состоянием. Ожидание не подтвердилось, и стоит записать чем.

**`#live` не мешает вовсе.** Страница с узлом React живой не объявляется —
`_shell` видит метку и не ставит ни обёртки `#live`, ни `data-reload`
(`live = active in LIVE_RELOAD and not _has_react_mount(body)`). У `react_shell`
её нет и подавно. Опрос панели ведёт сам экран через `useLive`, и оболочки он
не касается. Единственное, что осталось от старого механизма на React-ветке, —
ответ `_live_stale(request)` вкладкам, отрисованным по-старому; он стоит ДО
оболочки и переносом не задет.

**`_date_nav` не попал в модель, и это не отказ, а третий случай.** По четырём
условиям приёма в `frame.crumbs` он не проходит ни по одному: печатает его не
`_sec_page`, к общей оболочке он не относится, нужен ровно одному экрану и
зависит от даты, то есть является частью именно этого экрана. Но и «остановиться
и определять границу» повода нет: соседние экраны — `WeekScreen` и `DayScreen` —
**свою шапку дня уже рисуют сами**, каждый свою, и серверный `_date_nav`
остаётся у них только на легаси-ветке. То есть `/admin` был не сложнее
остальных, а просто позади них.

⭐ Отсюда правило приёмки, которого в списке не было: **прежде чем объявлять
требование новым, посмотреть, не решён ли он уже у соседа по группе.** Шапка
дня выглядела общей мебелью ровно до того, как обнаружилось, что общей она не
была никогда — три экрана рисуют три разные шапки, совпадающие только формой.
Попытка свести их в один компонент была бы рефакторингом против их различий.

## ⛔ Что нашлось по дороге: «Zi liberă» с двумя владельцами

На `/admin` фраза «Zi liberă — clinica este închisă» выводилась ДВАЖДЫ:
серверным баннером `_banner` по условию `eng.hours_for(d)` (только график) и
холстом React по условию `hours_of(d, live)` (график И записи). Условия разные,
поэтому расходились они не только числом копий:

| положение | сервер | экран |
|---|---|---|
| день закрыт, записей нет | «Zi liberă» | «Zi liberă» — **двумя строками** |
| день закрыт, запись осталась | «Zi liberă» | рисует сетку с записью |

Второе положение достижимо обычным путём: записали на рабочий день, потом
клиника убрала этот день из графика. Тогда баннер сообщал «clinica este
închisă» прямо над нарисованной записью. Записать в тот же день заново движок
не даёт (`msg=outside`), так что ловится это только сменой графика — и на
демо-профиле не ловится вовсе, там открыты все семь дней.

Владелец остался один — холст: у него условие полное. Это **исправление**, а не
переезд, и оно из того же класса, что 08-12 и 08-16: одно состояние, названное
в двух местах, расходится молча.

## Чего B1 не делает

Роутер и маршруты (B2), навигация без перезагрузки (B4), перенос авторизации в
React (не делается никогда), редизайн и Fluent (B5), Tauri (блок E), любые
правки адресов FastAPI.

## Что остаётся открытым намеренно

- **режим роутера** (declarative против data) — решается в B2, потому что от
  него зависит объём B3, а не B1;
- **границы коммитов B1** — не режутся заранее. Естественные швы покажет сам
  контракт, когда под него ляжет код; сегодня их называть рано.
