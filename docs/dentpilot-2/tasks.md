⭐ **P3 разделён на два (Олег, 20.09), и это не переделка плана.** P2 требует
от S0 доказать, где лежала старая установка, — а механизма доказательства до
установщика не существует. Писать P2 с заглушкой под P3 значит получить
искусственный этап, который нечем проверить. Поэтому:

| | Что это |
|---|---|
| **P3-min** | предусловие миграции: повышение прав, `Program Files`, `ProgramData`, `install.json`, нужные ACL и способ однозначно опознать старую установку |
| **P3-final** | конечный установщик ПОСЛЕ Tauri: настоящий бинарник, upgrade, uninstall, ярлыки, витрина, подпись, ассеты релиза |

⛔ В P3-min не заходит: финальный установщик под Tauri, UX, полный uninstall,
законченный поток обновления, подпись, упаковка релиза. Так установщик не
переделывается дважды целиком.

⭐ Внутри Tauri остаётся ВСЁ существующее: React, `/api/*`, FastAPI, SQLite,
бизнес-правила, интерфейс, тесты. Tauri — desktop shell, и только.

⛔ **Чего не делаем сейчас** (запрет на параллельные затеи):

- переписывать интерфейс, движок или заводить новый API;
- оживлять облачное издание;
- писать нового клиента — он уже написан дважды

## Правила, чтобы не застрять

1. **Один экран = один коммит = один флаг.** Не начинать следующий, пока
   предыдущий не включён у пилота или явно отложен.
2. **Экран не закрыт, пока его проверки не переписаны.** Зелёный прогон,
   потерявший смысл, хуже красного.
3. **Незапланированную находку не чинить на месте** — записывать строкой в этот
   файл и идти дальше. Иначе один экран съедает неделю.
4. **После каждого блока — полный прогон движка.** Без пайпа, иначе код выхода
   теряется.
5. ⛔ **Блок E не начинать**, пока блок C не закончен. Там точка невозврата.
   С 20.09 между ними встал блок **P**: Tauri обязан приехать уже в целевую
   раскладку, иначе переезд данных делается дважды и второй раз — поверх
   нативной оболочки.
6. Если задача не двигается два захода — **вынести в отдельную строку
   «отложено» с причиной**, а не бороться.
