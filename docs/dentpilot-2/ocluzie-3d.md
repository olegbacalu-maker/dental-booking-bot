## 3. Этапы

### Этап 1 — чистый модуль и положение по умолчанию

Новый `three/occlusion.ts` без React и без WebGL, как `arch.ts` / `pose.ts`:
- `type OcclRecord` — поля формы строками, как приходят с сервера;
- `type JawPose = { dx, dy, dz, yaw, pitch, pivotY, pivotZ }` и
  `ZERO_POSE`;
- `jawPose(rec, base, geo): JawPose`. `base` — замер прикуса модели
  (`{ oj, ob, relR, relL }`), `geo` — что нужно из раскладки (`z` и `x` 16/26/36/46,
  `z` 41, полуширина дуги). Правила — в приложении A, `apply()`:
  - `angle_*` → `dz` по стороне = `rel + сдвиг класса` (I → 0, II/1 и II/2 → −S,
    III → +S). Среднее двух сторон → `dz`, разница → `yaw = (dzR − dzL) /
    (2·полуширина)`. ⚠️ Сначала проверяй `'III'`, потом `startsWith('II')`:
    в прототипе эта ошибка превращала III в II;
  - если класса нет, а `overjet` есть, то `dz = base.oj − overjet`;
  - `overbite` → `dy = overbite − base.ob` (только когда нет открытого прикуса);
  - `deschisa` не пусто → `pitch` вокруг опоры `(y = 0, z = z46)` так, чтобы
    overbite стал записанным (без записи −3 мм). Угол доводится 2–3 шагами
    секущей по замеру, потому что поворот не линеен;
  - `mediana_mm` + `mediana_spre` → `dx` (`stanga` = `+x`, `dreapta` = `−x`);
- функции замера по точкам коронок: режущий край, губная поверхность у края,
  overjet и overbite. На вход массивы точек, без three.

Сцена (`scene.ts`):
- состояние `occ: JawPose` и `placeJaws` с поворотом вокруг опоры:
  `rotation = (pitch, yaw, 0, 'YXZ')`, `position = P + R·(pos0 − P)` (приложение A);
- `setOcclusion(pose: JawPose | null, animate: boolean)` с твином 700 мс через
  `tweens`, при `reduced` — сразу. `null` возвращает `ZERO_POSE`;
- зонд для стендов: `measureBite()` возвращает `{ oj, ob, relR, relL }` по
  текущим мировым матрицам.

Положение по умолчанию (только после «да» на Q1): правка источника, а не
постоянный сдвиг поверх. В `arch.ts › layoutArch` нижний `apex` с `−2.5`
перенести примерно на `+1` (это те же +3,5 мм, что `dz` прототипа) и сверить
замером. Десна берёт дугу оттуда же (`archProfile`, правило 24.10), отдельно
её не трогать.

Тесты: `occlusion.test.ts` (правила `jawPose` на числах, разбор III и II,
знаки `dx`, `yaw` при разных классах сторон); в `arch.test.ts` закрепить
прикус по умолчанию замером (overjet, overbite, `rel`) с допуском.

#### ✅ Этап 1 сделан 07.11.2026 (сессия ocl-pose, ветка `fix/ocl-pose`)

Модуль и сцена — как выше. **Положение по умолчанию — I класс по ориентирам**
(Олег 07.11 на Q1, кадры «как было / после» с числами —
`D:\DentProject\design\ocluzie-3d\q1\`): нижний `apex` −2,5 → **+0,3**
(`arch.LOWER_APEX`, правка источника; десна берёт дугу оттуда же). Замер модели:
бугор 16/26 в борозде 46/36 (0,00), overjet 2,70, overbite 1,39; было — бугор
впереди на 2,80, overjet 5,50. I класс в записи теперь не двигает челюсть по z,
II/III — на ∓`SCHEMATIC_CLASS_SHIFT_MM`.

⚠️ **Ограничение схемы: премоляры и клык — бугор к бугру.** Когда моляры в
I классе по ориентирам, клык и премоляры модели остаются на 2,5–3,6 мм в
сторону II (клык 13 впереди промежутка 43|44 на 3,6; бугор 44 позади
промежутка 13|14 на 2,6), и сбоку между ними видны ромбы до 4,3 мм. Моляры
при этом сомкнуты (наименьший зазор 16/46 −0,25 мм). Причина — пропорции
модели: нижний передний отрезок относительно широк (сумма ширин 43–33 —
83 % от 13–23; у Болтона ≈ 77 %), поэтому соотношение по молярам и по клыкам у
модели не совпадает. Подъём нижней челюсти этого не лечит (моляры уже
касаются), сдвиг `apex` ради клыков уводит моляры. Лечится раскладкой нижней
дуги — отдельная задача, не этот этап.

Отличия от текста этапа и почему:
- **Класс меряется по ориентирам, а не по центрам** (координатор 07.11, источник
  Олега AAPD, PMC3481985: у класса нет фиксированного числа мм, класс — где
  мезиально-щёчный бугор 16/26 относительно щёчной борозды 46/36).
  `occlusion.molarMark` находит их на сетке своей модели; `rel` = на сколько бугор
  впереди борозды по z. Без ориентиров (коронки-формулы) — по центрам с
  `REL_I = 1,3` мм. ⚠️ Замер: приближение прототипа «+2 мм» завышено на 0,7 —
  по ориентирам поправка 1,30 мм. Отсюда прикус по умолчанию — бугор впереди на
  **2,8** мм (а не 3,5), точный I класс — сдвиг нижней на +2,8 (overjet 2,7), а
  сдвиг прототипа +3,5 даёт бугор позади борозды на 0,7.
- **`S` — схема, не клиника (Q2, Олег 07.11):** «класс уже хранится, поэтому
  новое поле и миграция базы не нужны; сдвиг в сцене — условный визуальный
  ориентир, не измерение и не план лечения». Одна константа
  `SCHEMATIC_CLASS_SHIFT_MM = 4`; величины в записи нет и не будет, `jawPose`
  её не ищет. Подпись «schematic» на сцене — этап 3.
- **Прикус только при включённом «Ocluzie» (Q3, Олег 07.11):** «при выключенном
  переключателе сцена должна сохранять исходное положение модели» —
  предложение задания «x/z/yaw всегда» отклонено. `setOcclusion` запоминает
  ЗАПРОШЕННУЮ позу, `placeJaws` применяет `blendPose(поза, closeY / CLOSE_Y)`:
  включение «Ocluzie» ведёт позу тем же твином, что смыкание (при reduced —
  сразу), разомкнуто — ровно `ZERO_POSE`, группа нижней на (0, y, 0) без
  поворота, как до волны (держит `occlusion.test` › «поза только сомкнуто»
  через `Object.is`, живой зонд `__dpOccl.groups()`).
- **Поворот вокруг вертикали точный:** `yaw = asin(…)` и поправка `dz` на
  косинус; первым порядком (как в прототипе) разные классы сторон промахивались
  на 0,35 мм. Решается по ориентирам нижних моляров (`geo.z46`, `geo.half`).
- **Опора поворота** — `(0, 0, 0)` у резцов, кроме открытого прикуса (там
  `(0, 0, z46)`): поворот вокруг вертикали тогда не двигает записанную среднюю
  линию. ⚠️ Цена: при разных классах сторон моляры уходят вбок на
  `z46·sin(yaw)` (II справа + III слева — ≈ 4,7 мм) — вопрос к этапу 4.
- **Секущая открытого прикуса** — в `jawPose` через необязательный `probe`;
  сцена отдаёт его в `biteBase()` (`{ base, geo, probe }` сомкнутых челюстей при
  нулевой позе — то, что этапу 3 нужно для `jawPose`). Без `probe` — первое
  приближение `atan2`.
- **Твин позы:** точка опоры не едет вместе с углом (берётся у конца, где есть
  поворот), иначе челюсть по пути уплывала бы на (I − R)·ΔP.
- **Зонд для стендов** — `.odo-stage canvas.__dpOccl` (`measure`, `base`, `set`,
  `pose` → `{ want, applied }`, `groups`), как `__dpBench`: компонент (этап 3)
  не тронут.
- `arch.test.ts` закрепляет прикус по умолчанию (бугор в борозде ±0,05,
  overjet 2,7, overbite 1,39) и ориентиры (бугор +3,24 от центра 16, борозда
  +1,94 от центра 46).

Проверено опытом: живая сцена (headless Edge, SwiftShader) дала те же числа
`measureBite()`, что `biteAt` в тестах, до сотых, во всех трёх вариантах Q1.
