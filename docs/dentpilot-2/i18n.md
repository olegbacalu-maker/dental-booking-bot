# Контракт i18n и слоя Country — развилки, закрытые до кода

Ответ на видение «DentPilot Global» (21.09): один продукт, работающий в
нескольких странах и на нескольких языках. Этот файл **не заводит ни одной
локали и не открывает ни одной страны** — он закрывает развилки, каждая из
которых после первой правки стоит вдесятеро дороже. Прайор Олега буквально
про это: развилку протокола закрывать ДО экрана.

⚠️ Всё, помеченное ✅, проверено на коде командой, приведённой рядом. Числа
устаревают — **команда важнее числа**.

⛔ Решение «выходим в страну N» этим файлом НЕ принимается и им не
подготавливается. Признак, по которому страна вообще может быть конфигом, —
в памяти проекта (`global_country_config_or_product`): платит пациент напрямую
— близко к конфигу; участвует государство или страховщик — это отдельный
продукт с чужой сертификацией. Для DE и FR ответ «отдельный продукт»
окончательный, и никакой каталог строк его не меняет.

## 0. Что решается и что не решается

| Решается здесь | Не решается здесь |
|---|---|
| форма механизма: ключ, шов, дом каталога, кто решает язык | заводить ли вторую локаль (нет покупателя — нет локали) |
| границы: что переводится, что заменяется, что замораживается | выходить ли в страну (признак — см. выше) |
| чем это сторожится, чтобы не сгнило молча | когда делать перенос текста (после F, см. §12) |

## 1. Периметр: что вообще становится многоязычным

**React-поверхность + конверт `/api/*` + печать.** Легаси-страницы из
периметра **исключены навсегда**.

✅ Цена вопроса измерена: в серверных f-строках с румынским текстом **100%**
имеют подстановки, 114 из них зовут `_ic()` внутри себя, 99 мест склеивают
текст через `+`, 53 фразы запечатаны в HTML-литералы длиннее 400 символов.
Это и есть настоящая стоимость i18n панели — и мы её не платим: эти страницы
умирают вместе с миграцией в React.

⛔ Следствие, которое обязано быть ВИДИМЫМ: профиль с не-румынским
интерфейсом требует, чтобы все экраны были в React. Если `locale.ui != "ro"`,
а экран отдаётся легаси-страницей — программа отказывается стартовать с
названной причиной (какой экран, какой флаг), а не показывает румынскую
страницу посреди немецкого интерфейса. Пока `locale.ui == "ro"` ворота
инертны: у пилота и у Олега не меняется ничего.

✅ `grep -rl "^const T = {" frontend/src --include=*.ts* | wc -l` → 55 файлов;
`REACT_SCREENS` в `core/layout.py:924` → 20 имён из 24 экранов к переносу.
Остаток — четыре: C9 crypt, C10 system, C15 stats, C14+.

## 2. Ключ — точечный `ns.key`, а НЕ румынская строка

**Нет** строке-ключу. Четыре довода, последний решающий:

1. ~30 строк дублируются между файлами (чемпион — фраза про недоступный
   движок, 18 файлов); строка-ключ склеила бы их навсегда.
2. Род и число зашиты в слово: `finalizat` / `finalizată`,
   `șters` / `ștearsă` / `șterse`. Одинаковая румынская строка требует разных
   переводов по объекту.
3. Правка румынской формулировки становилась бы миграцией каталога.
4. ⛔ **Пропущенный ключ при строке-ключе выглядит ИДЕАЛЬНО по-румынски**, и
   сторож полноты не покраснеет никогда. Это ровно «полярность
   списков-исключений» из карты проекта.

`ns` — имя экрана или модуля, `key` — уже существующее имя из `const T` или
уже существующий код `MSG_BANNER`. Новых имён придумывать не надо.

## 3. Форма вызова: lookup прячется ВНУТРИ существующих точек

**Сервер.** ✅ `core/layout.py:354` — `MSG_BANNER.get(code, …)` внутри
`msg_json` — становится обращением к каталогу. Одна строка правки делает
многоязычными все вызовы `msg_json`, **ни один из них не трогается**
(`grep -rno "msg_json(" bot/app | wc -l` → 114, из них одно — определение).
Так же для `STATUS_LABEL`, `ALERT_KINDS`, `SOURCE_LABEL`, `_DOW_FULL` и для
текстонесущих полей моделей экранов (`label`, `status_label`, `badge.label`,
`title`, `hint`).

⛔ Тринадцать мест собирают баннер разметкой мимо словаря — их надо перевести
на коды, иначе «перевели MSG_BANNER» окажется неправдой. Найти:

```bash
grep -rnoE "banner (ok|err|warn)" bot/app --include=*.py | wc -l
```

**Клиент.** `const T = { … }` → `const T = t('ns', { …тот же объект… })`, где
`t` возвращает Proxy того же типа. Все обращения `T.save` остаются дословно
теми же; при `ro` каталог пуст и отдаётся сам объект из файла — **диффа
поведения нет**. Ключ резолвится в момент ОБРАЩЕНИЯ, а не на импорте, поэтому
порядок загрузки модулей безразличен.

⛔ Форма конверта `/api/*` не меняется ни на поле, новых маршрутов нет. Это
прямое требование порядка работ 20.09 («не заводить новый API»).

## 4. Дом каталога — сервер, один файл на локаль

`bot/app/i18n/<lang>.json`, вшит в сборку через `paths.resource()`.
Программа офлайн, установка одна, обновление exe обязано везти каталог как
ДАННЫЕ, а не как второй bundle.

`ro` **генерируется из исходников** скриптом — по образцу уже работающего
`scripts/gen_icons.py`, со сторожем свежести в `test_structure.py` (приём
готов и проверен на `icons.ts`: каталог отстал от кода → красный с командой
в тексте ошибки).

⚠️ Клиентская часть уезжает в страницу инлайн-скриптом. Правила живого
журнала действуют без исключений: ⛔ не внутри `#live`, объявлять `var`, не
`const` (повторный `const` при подмене — SyntaxError, и клик по свежей записи
молча перестаёт работать).

⚠️ Каталог — новый файл в сборке. `--add-data` потерять легко, и `/health`
этого не заметит: ловит только дымовой тест страниц (`tests/smoke_exe.py`,
вшит в `Build-Installer.ps1`). Значит генератор обязан существовать **до**
блока F.

⛔ Ни gettext, ни babel, ни ICU, ни react-i18next. `.venv-desktop` — окружение
сборки, всё лишнее уезжает в exe (единственное исключение за всю историю —
pyzipper, и он В САМОЙ программе). Свой формат на стандартной библиотеке.
И xgettext здесь всё равно бесполезен: литерала как целого не существует.

## 5. Кто решает язык — ОДНА функция, позапросно

`core/i18n.lang(request)`. Цепочка: явный `?lang=` (только печатные листы) →
язык пользователя → язык клиники (`clinic.json`) → язык по умолчанию для
страны → вшитый `ro`.

✅ Механизм уже есть и переиспользуется без изобретений: посредник
`_identify` (`main.py:92`) кладёт вошедшего в contextvar
(`core/auth.py:307`).

⛔ **Ни одной модульной глобали языка.** У клиники два рабочих места и три
роли; глобаль означала бы, что язык одного молча переключает текст другому —
и у разработчика с одной вкладкой это невоспроизводимо.

⚠️ Две тихие мины на будущее, если язык пойдёт в учётку:
`_as_user` (`core/auth.py:318`) строит УЗКИЙ словарь из четырёх полей — новое
поле до запроса просто не доедет, язык «сохранится» и не подействует; и любой
маршрут, пишущий `auth.json`, обязан звать `remember_auth_file()`, иначе
следующий старт покажет директору ложный «взлом» (это хуже настоящего:
клиника перестанет верить баннеру).

✅ Язык страницы зашит в СЕМИ местах (`core/layout.py` 1049, 1177, 1220,
1255; `main.py` 412, 473, 710) — становится вычисляемым. Заодно чинится
доступность.

## 6. Три оси, и они НЕ сводятся в одну

| Ось | Где живёт | Что решает |
|---|---|---|
| язык **пациента** | `patients.lang`, есть с 08-08 | печать 043/e, acord, выгрузка по 195-му |
| язык **оператора** | `clinic.json → locale.ui` (сегодня клиника = один язык персонала) | панель, ответы, модели экранов |
| **страна** | `clinic.json → locale.country` | набор печатных форм, нац-номер, валюта, пояс, список допустимых языков документа |

⭐ 043/e печатается на языке ПАЦИЕНТА, а кнопка «Printează» — на языке
РЕГИСТРАТУРЫ. Это не мелочь: сведение осей в одну даёт молчаливо неверный
лист.

⛔ **Формы государства не переводятся.** «Formularul nr. 043/e», «Ordinul MS
RM nr. 828 din 31.10.2011», «Legea nr. 195/2024», CNPDCP, IDNP — по ним лист
опознаёт проверяющий. Новая страна = **новый печатный модуль**, а не новый
язык в словаре. Туда же FAQ (`modules/settings/faq.py`): он цитирует Legea
195, CNAM и BitLocker — это страновой артефакт, а не перевод.

✅ Сегодня список языков размножен вчетверо: `LANGS` в `acord.py:195`,
`fisa043.py:166`, `plan_acord.py:241` и белый список в `db.set_patient_lang`
(`db.py:3217`). Сводится в один источник — это работа, полезная Молдове сама
по себе.

⚠️ Мягкий откат разводится на два разных исхода: «локаль не поддерживается» —
осознанный, но **видимый** фолбэк (отметка в ответе + строка в летописи);
«локаль поддерживается, ключа нет» — дефект сборки, падающий на проверке
паритета, а не доезжающий до подписываемого листа. Прямая аналогия с
`dpapi.unprotect`: «не расшифровалось» обязано отличаться от «пусто».

## 7. Летопись замораживается — с названной ценой

`activity.text` остаётся **готовой строкой на языке записи**. Колонки языка
нет, схема не трогается, структурированная запись (kind + параметры, сборка
при чтении) не заводится — это два пути чтения навсегда и ровно то
«строительство системы», которое остановлено 20.09.

**Цена принимается явно:** клиника, сменившая язык, получает двуязычную ленту
навсегда, и выгрузка по 195-му отдаёт строку как записана. Уже записанные
строки не переписываются — это ответ на вопрос «кто что сделал», а не
оформление.

**Ворота:** требование отдать выгрузку на языке ПАЦИЕНТА (в ЕС — art. 12
GDPR) открывает отдельный проект структурированной летописи. Сегодня он не
начинается.

⚠️ Вместо миграции — дешёвая проверка: каждая фраза события в каждой локали
≤ `EVENT_TEXT_MAX = 200` (`db.py:2442`). Обрезка молчалива, необратима, без
лога и без баннера; проектная фраза уже упиралась в потолок на румынском.
Потолок НЕ поднимаем — у клиник уже лежат строки этой длины.

## 8. Иконка — вне каталога

Каталог не хранит ни разметки, ни вызова `_ic`, ни svg. Иконку приклеивает
код рендера. Иначе ломается правило «интерфейс не просит знаки у Windows» и
его сторож, а 114 f-строк с `_ic` внутри пришлось бы переделывать дважды.

## 9. Множественное число — форма закладывается сразу, правила по надобности

Значение каталога это `str` **или** словарь категорий (one/few/many/other);
категорию выбирает функция по числовому слоту. Сегодня механизма нет вовсе, а
места, склеивающие число с замороженным словом, есть.

⭐ Это окупается не на третьем языке, а на ВТОРОМ, если второй — русский (три
формы): «21 записей» увидит пациент, а не тест. Правило для `ro` — тождество,
поэтому сегодня форма ничего не стоит.

## 10. Румынский — золотая локаль; вторую проверяет псевдолокаль

✅ Тесты прибиты к румынскому: сотни литералов в серверных и клиентских
наборах. Они **не правятся** — это и есть минимальный дифф.

⛔ Возникающая дыра называется прямо: зелёный прогон будет значить «румынская
сборка цела» и **ничего** про вторую локаль — ровно та же болезнь, что с
веткой Postgres, которую не исполняет ни один набор.

Закрывается ОДНИМ прогоном на псевдолокали, собираемой из `ro` механически
(обёртка + удлинение на 35–40%), файлом не хранимой. Она ловит три класса
разом: пропуск ключа, обход шва и переполнение — и не требует переводчика.

⚠️ Что псевдолокаль НЕ ловит без браузера: молчаливое ИСЧЕЗНОВЕНИЕ текста.
В `panel.css` десятки обрезающих правил плюс лестница `slim → tiny → bare` на
канве журнала; немецкое «Wurzelkanalbehandlung» превратится в многоточие, а
DOM-проверки найдут полный текст и позеленеют. **Риск назван и принят**:
замер делается стендом headless-Edge (в проекте уже есть) в день появления
первой настоящей локали, а не раньше.

⛔ Правки ширин ради длинного текста уводить в собственный CSS: `panel.css`
общая, и правка ради React молча меняет легаси-экраны, на которых сегодня
работает клиника.

## 11. Country — таблица ДАННЫХ, ни одного ветвления по стране

Строка таблицы: валюта и число её младших разрядов · пояс по умолчанию ·
шаблоны даты и времени · первый день недели · разделители · правило
нац-идентификатора · id юр-пакета и набор печатных форм · срок хранения ·
добавка к таблице свёртки диакритики.

⛔ Таблица заводится с ОДНОЙ строкой (MD). Вторая появляется вместе с первым
реальным покупателем. Абстракция, у которой одна реализация, — это ещё не
абстракция, а форма записи.

**Что уже дёшево сегодня:**
- ✅ пояс: `TZ` в `engine.py:18` — единственное определение `ZoneInfo` в
  `bot/`, все обращения идут через `eng.TZ`, значит правка доходит сама.
  Ставить ДО режима C (clinic_server + client): там сервер и рабочее место
  могут стоять в разных поясах.
- список языков документа (4 копии → один источник, §6).

**Что названо и отложено:**
- ⛔ валюта — **не настройка**: `price_mdl` / `amount_mdl` в именах колонок
  обеих схем, и деньги хранятся целым числом без младших единиц. Переезд на
  валюту с центами — миграция ДАННЫХ, а не строка конфига. Колонки НЕ
  переименовываются: имя косметично, несущая проблема — единица. Объявляются
  в одном месте как «сумма в валюте клиники, целое, основные единицы».
- форматы дат и времени, первый день недели, разделители тысяч;
- таблица свёртки диакритики — сегодня чисто румынская, и поиск «Muller» не
  найдёт «Müller»;
- нормализация кода страны в телефоне: идентичность пациента строится из
  голых цифр, и «+49 171…» с «0171…» дадут РАЗНЫЕ карточки — в Молдове это
  невидимо;
- ⛔ нумерация зубов: FDI входит в PRIMARY KEY четырёх таблиц. Для Европы это
  стандарт; Universal 1–32 для США — новая функция уровня данных, а не
  перенос.

⚠️ Шрифт ограничивает сам список возможных языков: вшиты четыре подмножества
Inter (latin, latin-ext, cyrillic, cyrillic-ext), программа офлайн и
подтянуть шрифт не может. DE/FR/IT/ES/RO/EN покрыты; греческий, вьетнамский,
иврит, арабица и CJK — нет, и обнаружится это у клиники, а не на машине
разработчика. Любой список стран сверять с unicode-range ДО обещаний.

## 12. Порядок: что внутри действующего плана, что после F

Порядок работ 20.09 не отменяется и не притормаживается. Внутри него — только
три вещи, каждая дешёвая ровно сейчас и полезная даже при исходе «второй
страны нет»:

1. **этот файл** (развилки на бумаге, ноль правок в дереве);
2. **ключи `country` / `lang` / `tz` в `clinic.json` — ВНУТРИ блока P**, там
   же, где решаются `clinic_id` и `device_id`. ⚠️ Отдельно потом — это второй
   переезд того же файла; `dental.env` так уже дважды терял канал `beta`.
   Завести ПОСЛЕ того, как P2 закроет оба входа миграции;
3. **сведение размноженных страновых словарей** в один источник + сторож в
   `test_structure.py` и строка в `mutate.py`. Это чинит нарушение
   собственного прайора «одно состояние — одно имя в ОДНОМ словаре».

Всё остальное — **после F (установщика)**. Довод инженерный, а не
дисциплинарный: правка, меняющая РАСКЛАДКУ, меняет и тексты — на хвосте P1
уже уехало семь пользовательских фраз, описывавших «рядом с exe». Переносить
текст в каталог, пока условия под ним двигаются, значит переносить его дважды.

⭐ Единственное исключение по срокам — клиентский шов (§3): его надо ввести
ДО того, как тронут C9, C10, C15 и C14+. Это последние 17% аргумента «экран
трогают один раз»; если опоздать, четыре новых экрана законно дошьют 56-й,
57-й и 58-й локальный словарь, пройдя всё ревью.

**Триггер у самого перевода — продажный, а не рабочий:** названный
иностранный клиент или заявление на сайте. Без него локаль протухнет раньше,
чем пригодится.

## 13. Стык с DentPilot Cloud (21.09)

Страна — атрибут ЛИЦЕНЗИИ и одновременно ключ локального файла. Это не
дублирование, а разделение источников истины: сервер — истина для БИЛЛИНГА
(цена, валюта счёта, какой юр-пакет продан), `clinic.json` — истина для
ПОВЕДЕНИЯ.

⛔ Иначе ломается граница, проведённая самим решением 21.09: программа не
умирает без интернета. Значит страна и язык не могут быть значением, которое
приходит с сервера в момент показа экрана. Правильная форма: сервер отдаёт
страну ПОДПИСАННЫМ claim (Ed25519, ключ вшит — схема уже принята), программа
кэширует его в файле, переживающем переустановку; расхождение файла и
лицензии = баннер директору, а не молчаливая перезапись.

⚠️ Отдельно и независимо от i18n: бумага
`clinics/lege-195/3-acord-furnizor.html` утверждает, что программа не создаёт
учётных записей на серверах поставщика — решение 21.09 это прямо отменяет.
Подписанных экземпляров нет ни одного, значит починка сегодня бесплатна, а
после первой продажи это уже расхождение подписанного документа с
архитектурой.

## 14. Чего не делаем

- ⛔ не переводим легаси-страницы (§1) — вместо перевода ворота;
- ⛔ не заводим i18n-библиотеку (§4);
- ⛔ не меняем форму конверта `/api/*` и не заводим новый API;
- ⛔ не переводим печатные формы государства и FAQ — это страновые артефакты;
- ⛔ не трогаем схему базы: `price_mdl` / `amount_mdl`, значение по умолчанию
  у автора события, FDI, MODVL, роли моста, статусы плана — это непрозрачные
  ключи, а не текст;
- ⛔ не структурируем летопись (§7);
- ⛔ не строим слой Country целиком (§11);
- ⛔ не правим тесты, завязанные на румынский (§10);
- ⛔ не делаем язык пер-пользовательским: шов готов его принять, но сегодня
  клиника = один язык персонала; включать вторую ось без клиента, который её
  просил, — редизайн внутри миграции;
- ⛔ не читаем локаль Windows: сегодня это ноль обращений, программа
  детерминирована от машины к машине;
- ⛔ не размораживаем Telegram-бота ради его словаря;
- ⛔ не переводим машинно юридические и медицинские тексты: 043/e и acord
  informat подписывает пациент.

## 15. Чем это сторожится

Каждое правило — проверка в `tests/test_structure.py` **и** строка в
`tests/mutate.py`; иначе правило записано, но не действует.

1. ⭐ **ЯКОРЬ ПЕРВЫМ**: каталог и `MSG_BANNER` на месте и непусты. Без него
   остальные правила позеленеют разом на пустом обходе — так устроена первая
   проверка каждого набора («исходники нашлись»).
2. Полнота локали: множество ключей совпадает с `ro`, пустых значений нет.
3. Паритет двуязычных словарей печати (сегодня в паритете, но не сторожится
   ничем). Закрывает трап, при котором отсутствующий ключ МОЛЧА выбрасывает
   строку из печатной 043/e.
4. Каждый код, уезжающий в `msg_json` или в редирект карточки, есть в
   `MSG_BANNER`. Сейчас пропуск даёт ПУСТОЙ текст, а клиент показывает
   «движок не отвечает» на успешном сохранении: HTTP 200, код верный, прогон
   зелёный.
5. Рядом с классом баннера нет литерального текста (13 мест, §3).
6. Свежесть сгенерированного каталога (§4).
7. Длина каждой фразы летописи в каждой локали ≤ 200 (§7).

⚠️ Правила 2, 3 и 4 — списки с ВКЛЮЧАЮЩЕЙ полярностью: переименуют каталог —
правило найдёт ноль нарушителей и позеленеет навсегда, а мутация не спасёт,
она ломает сторожа тем же устаревшим именем. Поэтому якорь и второй
независимый свидетель — падающий `--check` генератора.
