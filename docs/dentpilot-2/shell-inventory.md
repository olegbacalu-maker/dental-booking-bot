# B1: инвентарь серверной оболочки

Требование к этому файлу сформулировано жёстко и здесь не смягчается:

> инвентарь обязан описать существующую оболочку настолько полно, чтобы другую
> реализацию на React можно было **доказать** эквивалентной, **не сравнивая
> старый HTML** как контракт.

Поэтому у каждого куска не строка, а цепочка:

```
источник → условие → _shell → элемент HTML → кто читает сегодня → владелец в B1 → чем доказывается
```

Собрано разбором кода, 232 позиции в десяти областях. Ниже — не дамп, а то, что
несёт решение: полный перечень элементов, их владельцы в B1 и отдельно —
требование к ПЕРВОМУ КАДРУ, потому что причина мигания измерена и B1 обязан её
снять, а не перенести.

Точка входа: `_shell(body, sub, active="dash", bell=None, rail=False)` —
`bot/app/core/layout.py`. Зовут её **30 раз** из восьми модулей.

## 1. Сайдбар (34 позиции)

| Что | Условие | Владелец в B1 |
|---|---|---|
| `<aside class="side">`, `side-rail` (56 px) | `rail=True` — только одонтограмма и пародонтограмма | React Layout |
| шапка: SVG-знак, имя клиники, «DentPilot» | всегда; имя из `clinic.json` | React Layout |
| секция «Meniu»: Dashboard, Programări, Pacienți | всегда | React Layout |
| Medici, Statistici, Setări | по правам (`can(me, PERM_…)`) | React Layout |
| секция «Sincronizări»: Telegram Bot + точка `ok/off`, QR pacienți | за `tg_configured()` — **заморожено** | React Layout, шов сохранить |
| `class='on'` на активном пункте | `active` | React Layout |
| подвал `.sfoot`: `v{APP_VERSION}` · `<span id="sf_clock" data-tz>` | всегда | React Layout |
| `@media print{.side{display:none}}`, ≤640px — нижняя вкладочная полоса | всегда | React Layout |

⚠️ Значений `active` восемь: `pat` (11 вызовов), `prog` (4), `med` (4),
`dash` (4), `set` (3), `stat` (2), `qr` (1), `migration` (1). **`migration` не
совпадает ни с одним пунктом меню** — на этой странице не подсвечено ничего, и
это сегодняшнее поведение, а не дефект.

⛔ Ветка `me is None` отдаёт **полное** меню (облако без учёток). При переносе
её легко потерять: на демо-профиле она не срабатывает.

⭐ Единственная зависимость React от сайдбара сегодня — `#sf_clock[data-tz]`.
Цепочка целиком: `engine.TZ = ZoneInfo("Europe/Chisinau")` (жёсткая константа,
ключа пояса в `clinic.json` нет) → `_sidebar` печатает `data-tz` → `dashFx.clinicTz()`
читает. Часы в подвале пишет **только** `panel.js`, второй реализации нет.

## 2. Верхняя панель (23 позиции)

`.top` → форма поиска (`/admin/search`, чип `Ctrl K`), логотип клиники,
распорка, слот строки обновления, колокольчик, «Programare nouă», чип вошедшего
(аватар, имя, «роль · клиника»), выход.

⛔ **Колокольчик — заморожен вместе с ботом.** React-ветка `/admin`
(`schedule/routes.py`) зовёт `_shell(...)` **без** `bell`, легаси-ветка передаёт
`bell=new_today if tg_ui else None`. Сегодня незаметно: `tg_ui` ложно у всех.
Владелец в B1 — **не переносить поведение, сохранить шов `tg_configured()`**;
разморозить по невнимательности нельзя.

⚠️ Строка обновления видна всем ролям, но ведёт на `/admin/settings/system` под
`PERM_SETTINGS`: регистратура и врач получают 303 `no_access`. Дефект
сегодняшней шапки, не B1 — записан, не чинится здесь.

⚠️ `.toastbox{top:88px}` привязан к высоте шапки: смена высоты в B1 двигает все
плашки.

## 3. Рамка содержимого (26 позиций)

`.main` → `.content` → `<h1><a href="/admin">Registrul Clinicii</a></h1>` →
`.sub` = `{sub}` + `_sec_warn()` + `· v{APP_VERSION}` → четыре системных
баннера → тело → `.brandcorner` с `mailto`, несущим имя клиники и версию.

`_sec_warn()` живёт в `core/auth.py` и возвращает текст **только** в облаке без
`ADMIN_KEY`; у настольной клиники всегда пусто.

⛔ **Самая хрупкая часть переноса — сетка `.content`**, добавленная 24.09:

```css
.content{display:grid;grid-template-columns:max-content minmax(0,1fr);…}
.content>h1{grid-area:1/1/2/2}   .content>.sub{grid-area:2/1/3/2}
#root,.dp-react-root{display:contents}
.content>.nav:not(.nav~.nav),.dp-react-root>.nav:not(.nav~.nav){grid-area:1/2/3/3}
```

`display:contents` на `#root` и `.dp-react-root` — это то, чем **первая `.nav`
React-экрана участвует в сетке серверной оболочки**. То есть заголовок раздела и
навигация экрана стоят в одном ряду только потому, что узел React прозрачен для
раскладки. В B1 эти правила **переписываются под новую разметку, а не
переносятся** — утащенные как есть, они сломаются молча.

## 4. Баннеры (16 позиций)

Четыре системных подряд в `.content`, затем плашка ответа.

| Баннер | Условие | Кому | API сегодня |
|---|---|---|---|
| `_tamper_banner()` + кнопка «Am luat la cunoștință» | `auth_fp` разошёлся | директору | **нет** |
| `_split_banner()` | две картотеки на машине | директору | **нет** |
| `_slot_banner()` + список конфликтов | индекс брони встал не полностью | директору | **нет** |
| `_setup_hint()` | `CONFIG['template']` | всем | есть через `/api/settings/clinic` |
| `msg_banner(msg)` → `#dp_toast` | `?msg=` после 303 | всем | не применимо |

⛔ **Три из четырёх системных баннеров клиенту взять неоткуда** — ни один из 60
маршрутов `/api/*` их состояния не отдаёт. B1 обязан завести это, иначе
сигнализация подмены `auth.json` просто исчезнет с экрана.

⚠️ Паритет текста и паритет условия — разные задачи. Условия доказуемы
значениями (`tamper_alert() != ''`, `slot_guard()['pending']`,
`split_pending() is not None`, `CONFIG['template']`), тексты — нет.

⛔ И шире баннеров: `?msg=` — **единственный** канал ответа для всех серверных
форм, 98 кодов в `MSG_BANNER`, и работает он только потому, что после 303
документ перезагружается. Это ограничение B4, названное здесь заранее.

## 5. `<head>` и первый кадр (26 позиций)

Порядок в документе: `<!doctype>` → `<html lang="ro" data-style>` → charset →
viewport → `theme-color` (из темы) → favicon → `pwa_head()` (манифест,
apple-touch-icon, apple-mobile-web-app-\*) → `<title>{клиника} — registru}` →
`fonts.css` → `panel.css` → `<style>` переменных темы → инлайн-скрипт `anim` →
`<body data-v>` → сайдбар, шапка, h1, .sub, баннеры → **и только тут**
`bundle.css`, `#root` с заглушкой, `bundle.js` → `panel.js` в конце body.

⛔ `<style>` темы обязан идти **после** `panel.css`, иначе не перебьёт `:root`.
⛔ Скрипт `anim` обязан стоять **в шапке**: из конца `<body>` он опаздывает за
первую отрисовку и анимация идёт рывком назад.

⭐ **Главное для первопричины мигания.** `bundle.css` и `bundle.js` печатает
`react_mount`, и оба тега стоят **внутри `.content`**, после заголовка и
баннеров. Значит загрузка 452 КБ начинается только когда парсер дошёл до тела.
В документе **нет** ни одного `<link rel=preload>`, нет `<base>`, нет
`<noscript>`, нет `meta color-scheme`. Это самая дешёвая измеримая точка B1 —
и её нельзя «перенести» без замера (прайор о ложном красном стенде).

## 6. `<body>` и живой журнал (22 позиции)

`body[data-v]` (версия, **читает React**), `body[data-reload="12"]`, обёртка
`<div id="live" data-hash=md5>`, заголовки `X-DP-Live`, `X-DP-Hash`, `X-DP-V`,
`X-DP-Surface`, ответы 204 и 205, `Cache-Control: no-store`,
`<script data-live>` внутри живого куска.

Предикат:

```python
live = active in LIVE_RELOAD and not _has_react_mount(body)   # LIVE_RELOAD = {"dash","prog"}
```

Затронуты ровно четыре адреса: `/admin` и `/admin/week` (ключ `dash`),
`/admin/all` и `/admin/doctor/{dk}` (ключ `prog`).

⭐ Когда оболочку рисует React, теряется **не безопасность, а проверяемость**:
сегодня защита стоит в точке нарушения и спрашивает не флаг, а тело. Снимать
правило и его сторожа (`test_api.py` `suite_live_react`) нужно **вместе** —
оставленный сторож зовёт `_shell()` напрямую и останется зелёным навсегда,
доказывая свойство функции, которую никто не зовёт.

## 8. Что React потребляет из оболочки (25 позиций)

Связность через DOM оказалась **меньше ожидаемой** — ровно четыре точки:
`#root` (+`data-screen`, `data-params`, заглушка), `body[data-v]`,
`#sf_clock[data-tz]`, `html.anim`. Плюс ключи хранилища (`dp_seen_<день>`,
`dp_odo_view`, `dp_auto`) и участие в сетке `.content` через `display:contents`.

Из 411 CSS-классов, которыми пользуется React-разметка, 309 определены только в
`panel.css`, 91 — в `app.css`, 11 не определены нигде. Но «скрытый контракт
каркаса» в узком смысле — **один** класс (`.kbd`).

## 9. Права (26 позиций)

Состав меню, кнопки шапки и три баннера зависят от роли; роль читается **из
файла по id** при каждом запросе, поэтому понижение действует немедленно.

⛔ **Чего сегодня нет вовсе:** ни один JSON-маршрут не отдаёт роль, права, имя
вошедшего, имя клиники, версию, пояс или состояние бота. Эндпоинта «кто я» не
существует. Без него React-оболочку построить нельзя — это первый и
обязательный кусок серверной работы в B1, и он же единственный.

## 10. Чем доказывается паритет (16 позиций)

Приёмы в проекте уже есть, изобретать не нужно:

1. **модель оболочки** — чистая функция рядом с `_shell`, отдающая словарь
   (`active`, `sub`, `rail`, список баннеров, версия, пояс, тема, пункты меню);
   образец — `schedule/panel.py` + `test_panel_model`;
2. **перепись мест вызова** — разбор `ast` всех 30 вызовов `_shell(`, чтобы ни
   одно сочетание `active`/`sub`/`rail` не осталось неописанным;
3. **разовый мост модель ↔ старая страница** — один набор, доказывающий, что
   сегодняшний `_shell` печатает ровно то, что говорит модель. ⭐ Это
   **единственное** место, где старый HTML вообще трогается, и он объявляется
   одноразовым;
4. **генератор + сторож свежести** (идиома `gen_icons.py` → `icons.ts`);
5. **отрицательная половина** (`check_*_red.py`): сторож обязан краснеть на
   сломанном и зеленеть на исправном — иначе это не доказательство;
6. **сцена в браузере** — единственное, что говорит о первом кадре: прогон и
   jsdom о нём не знают ничего.

## Долги, записанные и отложенные

⛔ **Сторож «выключатель анимаций стоит в `<head>`» не может покраснеть.**
`tests/test_admin.py` делит страницу по литералу `<body>`, которого в документе
нет (оболочка печатает `<body data-v="…">`), поэтому `head` равен всей странице
и проверка зелена при скрипте в любом месте. Проверено конструктивно. Починка —
`split("<body")` плюс пара «красное на сломанном, зелёное на исправном».
**Решение Олега 24.09: вернуться после B1.**

⚠️ Колокольчик не доезжает до React-ветки (см. §2). Заморожен вместе с ботом,
не чинится.

⚠️ Строка обновления в шапке ведёт всех на раздел под `PERM_SETTINGS` (см. §2).
