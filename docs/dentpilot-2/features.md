# Экраны и порядок переноса

Полная таблица «маршрут → наборы тестов → число проверок» —
[screen-test-map.md](screen-test-map.md), она генерируется
(`python scripts/screen_map.py`).

Всего: **109 маршрутов**, **41 экран** (25 внутри общей рамки, 8
самостоятельных, 7 печатных, 1 фрагмент).

## Порядок

| Группа | Что | Почему здесь |
|---|---|---|
| **1** | настройки клиники, врачи, статистика, касса, QR | формы и таблицы, без живого опроса и печати |
| **2** | поиск, список, создание и правка пациента | данные есть, хрупкой графики нет |
| **3** | фиша, визиты, документы, анамнез, платежи | после разбора 909-строчной функции |
| **4** | одонтограмма, мост, пародонтограмма | самое хрупкое |
| **5** | журнал и живая сетка | последним, см. ниже |

Первый экран — **`Setări clinică`** (`/admin/settings/clinic`, 9 949 байт):
форма без опроса, без печати, без перетаскивания.

## Где закопаны мины

**Скобка моста** (`BRIDGE_DRAW_JS`). Меряет `offsetLeft` / `offsetTop` /
`offsetWidth` кнопок зубов, правит на инлайновую `--arc` потому что `transform`
не меняет `offsetTop`, резервирует место классом `.br-room` **до** замеров,
пропускает скрытую дугу и дорисовывает при переключении вида. В React — refs
плюс `ResizeObserver` плюс строгий порядок в `useLayoutEffect`. Самый хрупкий
кусок интерфейса.

**Ввод пародонтограммы** (`CHART_JS`). Автопереход к следующей точке, как
только число не может вырасти (2..9 сразу, 1 ждёт вторую цифру), клавиша `b`
для кровоточивости, пересчёт BOP% тем же счётом, что на сервере. Ввод построен
под диктовку: 192 числа иначе не вводятся никогда.
⚠️ Глубина 0 значит «не измеряли» (здоровая борозда 1–3 мм) — на этом держится
честность BOP% и средней глубины.

**Одонтограмма.** Сегодня в страницу уезжают **обе дуги** (до 104 SVG) и
переключает их CSS. В React это решается заново — и заодно лечится вес
страницы.

**Журнал — последним.** Живая подмена `#live` конфликтует со смонтированным
React-деревом. В том же коммите, где журнал переезжает, его ключ убирается из
`LIVE_RELOAD`. И живой журнал в React строится **поверх данных**, а не
разметки: сегодня отпечаток считается от строки HTML, и ради этого линию
«сейчас» пришлось унести в браузер.

## Критерий готовности экрана

```
[ ] React-реализация       [ ] состояния: загрузка / пусто / ошибка
[ ] эндпоинты API          [ ] бизнес-правила сохранены
[ ] права                  [ ] проверки переписаны на данные
[ ] валидация              [ ] флаг заведён и выключен
```

⭐ Экран **не считается перенесённым**, пока его проверки не переписаны.
Зелёный прогон, потерявший половину смысла, хуже красного.

## Раскатка на пилота

```
внутри → флаг выключен → пилот включает → отзыв → правка
```

При проблеме флаг выключается и клиника возвращается на старый экран **без
новой сборки**. Регистратура пилота обучена на нынешнем интерфейсе, поэтому
экраны включаются по одному, а не все разом.
