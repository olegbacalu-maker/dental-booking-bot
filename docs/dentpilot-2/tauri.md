## Как собрать и запустить

Rust — на D: (`D:\Rust`, Build Tools `D:\BuildTools`). Приложение Claude не
видит переменных пользователя — путь и переменные ставит сам запуск:

```powershell
powershell -File shell\dev\run.ps1 -Release -NoRun        # только сборка
powershell -File shell\dev\run.ps1 -Fake demo             # подставной движок
powershell -File shell\dev\run.ps1 -Fake bridge           # настоящий сервер под подставным DP1
powershell -File shell\dev\run.ps1                        # движок bot\desktop.py (DENTART_SHELL=tauri, Т5)
```

`run.ps1` ставит `RUSTUP_HOME`/`CARGO_HOME`/`TMP` на D:, `CARGO_TARGET_DIR`
(по умолчанию `sandbox\tauri-shell-run\target`), порт 8094, данные и профиль
окна — в `sandbox\tauri-shell-run`. ⛔ 8088 — живая установка Олега.
Сборке нужен Python программы (`.venv-desktop`, в нём PIL): им рисуются
заставка и значок; готовой оболочке Python не нужен.

Где оболочка ищет движок (контракт § 1): `<папка exe>\engine\DentPilot-Engine.exe`;
нет — `DENTPILOT_DEV_APP` (venv-python + `bot\desktop.py`, рабочая папка
`bot\`). Только для разработки: `DENTPILOT_DEV_ENGINE` подменяет скрипт
(подставной движок). Движок из исходников требует `DENTART_DATA_DIR` и порт
— их даёт окружение, оболочка их не передаёт.

## Как устроено — и почему

- **Заставка — своя страница оболочки** с видом нынешней: те же знак, слово,
  фон, шрифт Inter (рисует `assets.py` из `brand.py` при сборке). Цвет клиники
  приходит словом `hello`; до него — последний цвет из `shell.json` (`?c=`),
  без вспышки бирюзы у синей клиники. Этапы — `stage`, беда — `fatal` (текст и
  путь к журналу), минимум показа 0,9 с, затухание 0,45 с — как у лаунчера.
- **Канал `dpShell.send`** — `chrome.webview.postMessage`, без перехода:
  `beforeunload` страницы не просыпается (опыт: форма «nesalvat» — 0
  срабатываний). ⚠️ Форма сообщения — строка вида запроса IPC Tauri с чужим
  ключом `dpShell`: обработчик Tauri стоит в цепочке WebView2 первым, объект
  он не читает и цепочку обрывает (сообщения до нас не доходили), строку не
  того вида разбирает с ошибкой в консоль страницы, а запрос с чужим ключом
  отбрасывает молча. Прав IPC это странице не даёт. Чьё сообщение — по адресу
  приславшего документа: программа — только с адреса движка.
- **`dpShell` только у адреса движка**: вставка проверяет `127.0.0.1`, переход
  на чужой порт 127.0.0.1 оболочка не пускает, чужие адреса уходят в браузер
  Windows (`target=_blank` — тоже; своё `_blank` — в этом же окне).
- **Меню**: при каждом открытии — `dpMenu(id)` страницы (ждём 0,7 с); нет
  функции (вход, PIN, восстановление, печатные листы — бандла там нет) или
  ответа — запасной список оболочки: «Închide DentPilot…», правка, масштаб,
  весь экран. Клавиши — текстом после табуляции (их ловит страница), `&` —
  удвоено. `act:`/`go:` → `dpRun`; `go:` без `dpRun` — переход по адресу.
- **Клавиши браузера WebView2 выключены** (как в окне pywebview): F5, Ctrl+P,
  Ctrl+F, Ctrl+плюс ловит страница по одному списку и шлёт `win/*` сюда.
  Правка в поле (Ctrl+C/V/X/A/Z/Y) работает. Масштаб — шаги 67–175 %, в
  `shell.json`.
- **Перетаскивание**: обработчик перетаскивания Tauri выключен на всех WebView
  (`disable_drag_drop_handler`, 22.10): на Windows он подменяет цель броска
  WebView2 своей (только файлы), и HTML5-перенос визита не работал в
  2.0.0–2.0.3. Аргументы браузера — `main.rs::BROWSER_ARGS` (умолчания wry +
  `--lang=ro`, поле даты «zz.mm.aaaa»), одни у bar/app/watch. Стенд —
  `shell/dev/dnd_stand.py` (мышь ОС).
- **Правая кнопка**: родное меню WebView2 оставлено только про правку — в поле
  (отменить … выделить всё, без «Эмодзи»), на выделенном — «копировать», на
  странице — ничего. Подписи — языком браузера (`--lang=ro`, выше; глазами
  не сверено), до 22.10 — языком Windows.
- **Скачивание** — родное окно «Сохранить как» (папка «Загрузки», имя от
  сервера), модально внутри события WebView2, как это делало окно pywebview.
  ⚠️ Второе скачивание со страницы Edge держит вопросом «сайт хочет загрузить
  несколько файлов» — с адреса движка оболочка разрешает сама.
- **Печать** — `window.print()` страницы открывает предпросмотр Edge в окне.
- **Крестик** прячет окно к часам, если свой движок жив; движка нет (беда,
  `busy`) — выход. Первый раз — подсказка уведомлением, без паспорта Windows —
  окном (`shell.json` › `tray_hint`). Выход — меню значка «Ieșire din
  DentPilot» или «Închide DentPilot complet…», с вопросом; `quit` движка —
  без вопроса.
- **Остановка движка**: `{"v":1,"cmd":"stop"}` + закрытый stdin; 10 с — снять
  задание. ⛔ stdin — труба на всю жизнь движка (NUL = «стоп» сразу).
  ⛔ Оболочка движок не перезапускает: падение — заставка с текстом беды
  («s-a oprit neașteptat») и окно на экран.
- **Один экземпляр** — плагин Tauri по `identifier`; второй запуск показывает
  окно первого, `--tray` (автозапуск) — нет. Стенд (`DENTART_PROFILE_DIR`)
  берёт свой замок, иначе показал бы окно установленной программы.
- **`--tray`**: окна нет, подсказки нет, движок как обычно; развёрнутое окно
  развернётся при первом показе. `warn` движка ждёт, пока окно покажется.
- **Общий ПК** (`ready.session == "clear"`): куки профиля снимаются до первого
  входа и при каждом прятании к часам (и программа уходит на вход).
- **Память окна** — WINDOWPLACEMENT: Windows сама хранит «обычное» место
  отдельно от развёрнутого (по событиям «растянули» разворачивание записало бы
  обычным местом весь экран). Не целиком ни на одном экране — посередине.
- **Пути**: профиль WebView2 — `%LOCALAPPDATA%\DentPilot\webview`
  (стенд — `DENTART_PROFILE_DIR`; режим флешки `portable.flag` снят 22.10.2026);
  `shell.json`, `shell.log` (+ `shell.log.1`) — `%LOCALAPPDATA%\DentPilot`
  (стенд — рядом с его профилем). Журнал открывает только первый экземпляр.
- **Паспорт процесса** `md.dentpilot.app` (`SetCurrentProcessExplicitAppUserModelID`).

## Паника и повторный старт (18.10, к 2.0.1)

- **Паника — строка в журнал.** У release `panic = "abort"`: паника — сразу
  конец процесса (AppCrash `c0000409`, данные 7 = FAST_FAIL_FATAL_APP_EXIT),
  окна с текстом нет, движок гасит задание без слова `stop`. Хук
  `paths::panic_hook` (первая строка `main()`, значит, и у сторожа) успевает
  дописать `PANIC <сообщение> at <файл:строка> thread=<имя> tid=<n>` в
  `shell.log` (у сторожа — `watch.log`); журнал ещё не открыт (до `setup`) —
  дописью в `shell.log` по пути. Сам хук не паникует: имя потока —
  `GetThreadDescription`, не `thread::current()` (она паникует после
  разрушения TLS потока), замок журнала — `try_lock`.
- **Причина падения на стенде Т9 (17:36, 1 из ~20 прогонов)** найдена по
  минидампу Windows (`%LOCALAPPDATA%\CrashDumps\DentPilot.exe.<pid>.dmp`):
  оболочка, пересобранная из того же коммита (тот же rustc, `--locked`),
  совпала с дампом байт в байт по коду у места падения, а карта линкера
  (`cargo rustc --release -- -C link-arg=/MAP:…`, код от неё не меняется)
  назвала стек: `tao` → `tauri::App::make_run_event_loop_callback` (Ready) →
  `setup` вернул `Err` → `panic!("Failed to setup app: {e}")` (tauri 2.12.1
  `app.rs:1444`). В регистрах XMM — обрывки текста: WebView2 ответил
  0x800700AA ERROR_BUSY. Повторный старт (выход → сразу запуск на том же
  профиле) застал WebView2 прошлого запуска ещё живым. Тот же путь — у
  перезапуска сторожем (новая оболочка — сразу за выходом старой).
- ⛔ **В `setup` нет ни одного `?`**: его ошибку Tauri делает паникой. Окно и
  оба WebView — `open_window`; WebView — с повтором (`add_webview`: раз в
  0,5 с до 20 с, каждая попытка — строка журнала `WebView2 <кто>: not created
  (try N)`); не вышло — окно Windows с текстом («Detalii:» — ошибка) и выход 1
  (`cannot_start`); так же — ошибка `Builder::build`. Сторож без окна
  работает без экрана, а не падает.
- **Опыт без гонки** — `shell/dev/busy_stand.py`: профиль окна держит другой
  WebView2 (сторож на том же профиле с другими аргументами браузера — WebView2
  отвечает 0x8007139F). 2.0.0 — `0xc0000409` за 6,6 с, без текста и без строки
  в журнале; исправленная — 9 повторов, окно на 10-м через 5,0 с после
  освобождения, выход 0; профиль занят дольше 20 с — текст через 22 с, код 1.
  ⚠️ Окно-сообщение стенд закрывает `WM_CLOSE`: `WM_COMMAND IDOK` его не берёт.
- **Сама гонка редкая**: 100 прогонов `scripts/shell_check.py` (50 на 2.0.0,
  50 на исправленной — все 22/22) и 60 кругов «выход → сразу запуск» (со
  снятием задания и без, как у сторожа) — ни одного ERROR_BUSY; у Т9 она
  случилась 1 раз из ~20 под нагрузкой сборки. Поэтому проверка — стенд
  занятого профиля, а не повтор стенда пары.
- **Читать аварию без символов**: AppCrash `c0000409`/7 со смещением
  `rust_panic` этой сборки — паника Rust (у 2.0.0 — `0x1e97c5`, у пробной
  1.46.1 — `0x1e1f75`); минидамп — `%LOCALAPPDATA%\CrashDumps`. Тот же коммит,
  тот же rustc и `--locked` дают тот же код — так пересобранная копия с
  картой линкера называет функции дампа.

## Уведомления Windows — что видно где

Проверено 18.10 на Windows 11: баннер у часов показывается, только если в
«Пуске» есть ярлык с паспортом `md.dentpilot.app` (подпись — имя ярлыка,
значок — его). Без ярлыка Windows на вопрос `Setting` отвечает ошибкой
0x80070490, а показанное молча уходит в историю без баннера — запись паспорта
в `HKCU\Software\Classes\AppUserModelId` этого не меняет. Поэтому:
- **установщик (Т9)** обязан прописать `AppUserModelID: "md.dentpilot.app"`
  в ярлык `{autoprograms}` (Inno `[Icons]`);
- **в разработке** уведомлений нет: оболочка видит, что Windows её
  не знает, подсказку «я у часов» показывает окном, уведомления движка
  помечает показанными (то же скажет баннер внутри программы);
- для опыта в разработке — временный ярлык в своём «Пуске» с этим паспортом
  на собранный exe (после — удалить).

Клик по уведомлению — окно на экран и `go:<open>`; показанные id — в
`shell.json` (200 последних), сбой Windows — спросим снова через 30 мин.

## Место на диске

Rust и Build Tools — на D:. `target/` отладочной и release-сборки — 1–3 ГБ:
держать на D: (`CARGO_TARGET_DIR` вне репозитория или `shell\target`,
закрытый `.gitignore`). Холодная отладочная сборка — 2,5 мин, повторная —
10–20 с.
