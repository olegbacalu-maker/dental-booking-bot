# Tauri: контракт между частями

18.10.2026, начало перехода (путь Б, разбор
`D:\DentProject\review\windows-app-tauri-2026-10-18.md` § 11–12). Части делают
разные сессии одновременно — этот файл и есть то, о чём они договорились.
⛔ Меняется только через главную сессию перехода: часть, которой нужно другое,
пишет туда, а не правит контракт молча у себя в ветке.

Версия контракта — **1** (поле `v` во всех сообщениях ниже).

```
DentPilot.exe  (оболочка Tauri 2, Rust)        ← ярлык, сторож обновления, второй запуск
 ├─ окно: полоса меню (своя страница) + программа (WebView2, http://127.0.0.1:<порт>)
 ├─ значок у часов, уведомления, память окна, один экземпляр
 └─ движок: engine\DentPilot-Engine.exe        ← PyInstaller папкой (onedir)
       = bot/desktop.py в режиме движка: папка данных, ключи, копия, сервер
```

## 0. Что не обсуждается

- Окно открывает `http://127.0.0.1:<порт>/…`, ⛔ не `tauri.localhost`
  (кука `samesite=lax`, `same_origin_post`, `client_is_local` — `tauri.md`).
- ⛔ Обновлятор Tauri не включать — обновление остаётся нашим (`updates.md`).
- ⛔ Движок — не служба и не SYSTEM: работает под учёткой человека (ключ базы
  под DPAPI, `sidecar.md`).
- ⭐ До сборки Tauri (пункт Т9) `app` main остаётся выпускаемым ПРЕЖНЕЙ
  сборкой (onefile + pywebview). Всё новое спит без оболочки: режим движка
  включает переменная, слой команд React — только при `window.dpShell`.
  Окно pywebview снимается отдельным шагом после приёмки (Т11), не раньше.
- Тексты оболочки — румынские, без эмодзи и знаков вне Inter (правило
  CLAUDE.md «ничего графического от Windows»).
- Версии Tauri и плагинов закреплены `=` (сегодня `tauri =2.12.1`,
  `tauri-build =2.7.1`, `tauri-plugin-single-instance =2.5.1`). Tauri 3 — альфа,
  на 2.x.
- Идентификатор программы и паспорт ярлыка (AppUserModelID) — **`md.dentpilot.app`**:
  его ставит оболочка (`tauri.conf.json`) и прописывает установщик в ярлыки;
  без совпадения Windows не покажет уведомления.

## 1. Раскладка

```
C:\Program Files\DentPilot\
  DentPilot.exe                  оболочка; другого exe ярлык и сторож не знают
  install.json, portable.flag    корень программы (BASE) — папка DentPilot.exe
  engine\DentPilot-Engine.exe    движок
  engine\_internal\…             PyInstaller onedir
```

- ⭐ В режиме движка **BASE — папка DentPilot.exe** (родитель `engine\`), а не
  папка движка: `install.json`, `portable.flag` лежат там. Папка данных
  считается как сегодня (`DENTART_DATA_DIR` → `portable.flag` → `ProgramData`).
- Разработка: собранного движка нет — оболочка берёт `DENTPILOT_DEV_APP`
  (путь к `app\`) и запускает `<app>\.venv-desktop\Scripts\python.exe
  <app>\bot\desktop.py` с рабочей папкой `<app>\bot`. Собранный движок рядом
  важнее переменной.
- Профиль WebView2 (вход переживает перезапуск) решает **оболочка**:
  `%LOCALAPPDATA%\DentPilot\webview`, при `BASE\portable.flag` — `BASE\webview`
  (те же пути, что `desktop.profile_dir()` сегодня). Он нужен ей до первого
  слова движка — окно с заставкой создаётся сразу.
- Своё состояние оболочки (окно, показанные уведомления) —
  `%LOCALAPPDATA%\DentPilot\shell.json`, по учётке Windows.

## 2. Оболочка ↔ движок (Т5 ↔ Т6)

### Запуск
Оболочка запускает движок со своим окружением плюс:

| Переменная | Значение |
|---|---|
| `DENTART_SHELL` | `tauri` — режим движка |
| `DENTART_SHELL_TOKEN` | 32 случайных hex на каждый запуск (раздел 4) |

Порт, папку данных, LAN, режим установки решает **движок**, как сегодня
(`dental.env`, `DENTART_PORT`). Оболочка их не передаёт и не угадывает; в
разработке они приходят обычным окружением.
⛔ Движок ИЗ ИСХОДНИКОВ без `DENTART_DATA_DIR` отвечает `fatal` и кодом 2 —
иначе он открыл бы `%ProgramData%\DentPilot`, живую картотеку. Оболочка в
разработке обязана передать `DENTART_DATA_DIR` и `DENTART_PORT` (не 8088).

Движок в режиме `DENTART_SHELL=tauri`:
- не импортирует pywebview, не открывает браузер, не рисует окон
  (`MessageBoxW` — тоже нет: беда уходит событием `fatal`);
- порядок шагов запуска — прежний (`sidecar.md` › «Порядок шагов»);
- живёт в «задании» Windows оболочки (Job Object, KILL_ON_JOB_CLOSE, старт
  приостановленным — как в песочнице `engine.rs`).

### Движок → оболочка: строки stdout
Каждое сообщение — одна строка `DP1 <json>`, JSON в ASCII (диакритика —
`\uXXXX`). В stdout движок не пускает ничего, кроме этих строк; stderr он сам
уводит в `data\dentpilot.err.log`, трубу stderr оболочке читать не нужно (лог
движка — по-прежнему `data\dentpilot.log`). Незнакомую строку или событие
оболочка пропускает.

| `event` | Поля | Когда |
|---|---|---|
| `hello` | `version`, `color` (`#RRGGBB` темы клиники), `pid` | сразу после чтения темы — заставка и полоса меню красятся до готовности |
| `stage` | `text`, `pct`, `upto` | этапы запуска — те же, что сегодня идут в `dpStage` |
| `ready` | `url` (`http://127.0.0.1:<порт>/admin`), `port`, `session` (`keep`/`clear`), `data` (папка данных), `lan` (bool) | сервер ответил `/health` |
| `busy` | `url` | порт уже обслуживает другой экземпляр DentPilot (вторая учётка Windows, стенд) — оболочка показывает этот адрес без своего движка |
| `warn` | `text` (румынский, для человека) | запуск идёт, но человеку надо знать (нечитаемый `install.json`, битый `DENTART_PORT` — в окне pywebview это было окно Windows); оболочка показывает без остановки запуска, когда окно на экране |
| `fatal` | `text` (румынский, для человека), `log` (путь; пустая строка, если папки данных нет) | запуск невозможен (порт чужой, папка данных, сервер упал); затем выход с кодом 2 |
| `quit` | `reason`: `update` / `restart` | движок просит оболочку закрыться СЕЙЧАС, без вопроса: сейчас пойдёт установщик или сторож перезапуска (Т10) |

### Оболочка → движок: stdin
- строка `{"v":1,"cmd":"stop"}` или **закрытый stdin** = честно остановиться:
  uvicorn `should_exit`, фоновые циклы, соединения с базой закрыты, выход 0.
  Движок сам укладывается в 8 с, дальше выходит жёстко. Закрытый stdin — это и
  «оболочка исчезла» (третья страховка `sidecar.md`). ⚠️ Закрывать базу
  обязательно: без этого процесс после остановки uvicorn сам не выходит
  (находка Т5).
- Через 10 с без выхода оболочка снимает задание (`TerminateJobObject`).
- Коды выхода: 0 — остановлен, 2 — `fatal`, 3 — `busy`.

### Второй запуск
Первой отвечает оболочка (плагин одного экземпляра: второй запуск показывает
окно первого, даже спрятанное у часов). Мьютекс движка (`_claim_instance`)
остаётся страховкой и даёт `busy`.

### Запуск вместе с Windows
Галочка в Setări (Олег 18.10: по учётке Windows, по умолчанию выключена; на ПК
с доступом с телефонов — подсказка включить). Пишет её **движок** (он работает
под той же учёткой): значение `DentPilot` в
`HKCU\Software\Microsoft\Windows\CurrentVersion\Run` =
`"<BASE>\DentPilot.exe" --tray`; только в режиме движка (в разработке и в
окне pywebview галочки нет). Оболочка с `--tray` стартует сразу у часов: окно
не показывает, подсказку «я у часов» не показывает, движок запускает как
обычно.

### Общий ПК
`ready.session == "clear"`: оболочка снимает вход при старте и при каждом
прятании окна к часам (крестик), не только при выходе — иначе следующий
человек откроет программу кликом по значку от чужого имени.

## 3. Оболочка ↔ экраны React (Т6 ↔ Т7)

### Что вставляет оболочка
В каждую страницу с адреса `http://127.0.0.1:<порт>` (и только туда) до её
скриптов:

```js
window.dpShell = { v: 1, version: '<версия оболочки>', send(path) { … } }
```

`send('win/zoomin')`, `send('ctx')` — команда оболочке; как она доходит
(отменённый переход на `http://dpcmd.localhost/…`, свой протокол и т. п.) —
дело оболочки. ⛔ Удалённой странице не выдаются права IPC Tauri: экраны
ничего, кроме `send`, у оболочки не зовут. Нет `window.dpShell` (браузер
второго ПК, телефон, окно pywebview) — нет меню, нет слоя команд и клавиш
(решение Олега 18.10: в браузере меню не нужно).

### Что даёт страница (только при `window.dpShell`)
| Функция | Что возвращает / делает |
|---|---|
| `window.dpMenu(id)` | `{v:1, items:[{id, label, accel?, enabled} \| {sep:true}]}` для `id` из `file`, `edit`, `view`, `go`, `help`; пункты — по правам вошедшего, «Mergi la» — из `nav.items`, «Tipărește»/«Exportă» серые, если экран их не заявил |
| `window.dpRun(id)` | исполнить пункт `act:*` или `go:*` |
| `window.dpCtx()` | `{v:1, color, logged, title}` — для цвета полосы и пунктов значка |

Оболочка зовёт `dpMenu` при КАЖДОМ открытии списка (всегда свежее), `dpCtx` —
после загрузки страницы и по `send('ctx')`; страница шлёт `ctx`, когда сменился
человек, тема или вход.

### Пространства имён пунктов
| Префикс | Исполняет | Примеры |
|---|---|---|
| `act:` | страница | `act:newAppt`, `act:newPatient`, `act:print`, `act:export`, `act:backupNow`, `act:quickfind`, `act:reload`, `act:back`, `act:forward`, `act:switchUser`, `act:about` |
| `go:` | страница (роутер) | `go:/admin/all` |
| `win:` | оболочка | `win:zoomin`, `win:zoomout`, `win:zoom0`, `win:fullscreen`, `win:datafolder`, `win:mail`, `win:quit` |
| `key:` | оболочка (нажатие в поле с курсором) | `key:z`, `key:y`, `key:x`, `key:c`, `key:v`, `key:a` |

- Один список команд — в React (подписи, клавиши, права). Оболочка подписей
  пунктов не держит; её собственные — только заголовки полосы (Fișier ·
  Editare · Vizualizare · Mergi la · Ajutor), меню значка у часов и вопрос
  «закрыть».
- Клавиши (Ctrl+N, Ctrl+Shift+N, Ctrl+P, Ctrl+F, F5, F1, F11, Ctrl+1…6,
  Ctrl+=/−/0, Alt+←/→) ловит страница по тому же списку; `win:*` из них
  уходит в `dpShell.send('win/<имя>')`. Ctrl+Z/Y/X/C/V/A в поле — родные.
- «Despre DentPilot» — окно страницы (`act:about`): версия программы, версия
  оболочки (`dpShell.version`), клиника, папка данных, лицензия до.

## 4. Уведомления (Т8 → Т6)

- `GET /shell/notices` — только при `DENTART_SHELL_TOKEN`, только с
  127.0.0.1 и только с заголовком `X-DentPilot-Shell: <токен>` (сравнение
  постоянного времени); иначе 404. Без сессии и без данных пациентов.
- Ответ: `{"v":1, "items":[{"id", "title", "body", "open"}]}`; `open` — путь
  экрана (`/admin/settings/system`, лицензия, SMS).
- `id` детерминирован и меняется только тогда, когда событие надо показать
  СНОВА: `update:<версия>`, `license:<valid_until>:<порог>`,
  `sms:<порог>:<ключ эпизода>`. Сервер не помнит, что показано, — помнит
  оболочка (`shell.json`), по учётке Windows.
- Оболочка спрашивает после `ready` и раз в 30 минут; клик по уведомлению —
  окно на экран и `dpRun('go:<open>')`.
- Три уведомления (Олег 18.10): вышло обновление, лицензия кончается, SMS
  осталось мало. Про пациентов — ничего.
- Пороги (Олег 18.10): лицензия — за **7 и за 1 день** до конца (продлилась
  сама — молчать); SMS — **по штукам**: платный остаток **30** и меньше, в
  пробном — **10** и меньше. ⛔ Одно правило «мало SMS» — одна функция для
  уведомления, баннера и значка у пункта меню; прежний порог по дням
  (`LOW_DAYS`) уходит, тексты про «дни» — тоже.
