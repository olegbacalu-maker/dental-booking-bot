## Шаг 1 — вкладки (26.09.2026)

| вкладка | `?tab=` | что внутри |
|---|---|---|
| Rezumat | (умолчание, в адрес не пишется) | ближайший визит, быстрые действия, летопись · справа предупреждения и история визитов |
| Odontogramă | `odonto` | рабочий стол одонтограммы — тот же, что на детальной (шаг 2) |
| Parodontogramă | `perio` (+ `exam=`) | лист пародонтограммы — тот же, что на странице (шаг 3) |
| Plan și plăți | `plan` | план лечения и сальдо/платежи |
| Vizite | `vizite` | история визитов · справа ближайший визит |
| Documente | `docs` | документы |
| Date pacient | `date` | профиль (правка, архив, стирание) · справа анамнез |

Контракт адреса:
- вкладка — в query, как режим ленты `?views=1`; оба собирает `qs(tab, views)`,
  умолчания не пишутся, прежний `?msg=` не тянется;
- переход по вкладке — роутером с `replace` (щелчки не копят «Назад»); F5
  открывает ту же вкладку; смена query на том же пути фишу не перечитывает
  (`searchChangeKeepsData`) — журнал доступа лишнего «Fișa deschisă» не получает;
- адреса действий вкладку НЕ несут (`a.views` — только режим ленты);
- неизвестное значение `?tab=` = Rezumat.

Монтирование: активна ОДНА вкладка, остальные размонтированы. Следствие для
одонтограммы: модель едет с фишей в загрузчике (`Promise.all`, первый кадр без
прыжка), а после любого действия фиша приезжает без `odontogram`, и карточка
при возврате на вкладку грузит свежую модель сама — этот GET не открытие фиши.

Связи между вкладками: зуб из плана → вкладка Odontogramă с открытым диалогом
зуба (просьба с меткой применяется, как только у карточки есть модель);
быстрые действия Rezumat → соответствующие вкладки; «Deschide planul» из окна
KPI → вкладка плана; «назад» с детальной одонтограммы и пародонтограммы →
`?tab=odonto`.

Клавиатура (Fluent TabList): `role=tablist`/`tab`/`tabpanel`, у активной
`tabIndex 0`, у остальных -1; ←/→ по кругу, Home/End; фокус идёт за вкладкой.

Где проверяется: `PatientCardScreen.test.tsx` (тур по вкладкам с `opens() === 1`,
адрес/F5, вкладка + режим ленты, быстрые действия и зуб из плана, клавиатура);
стенд `scripts/spa_nav.py` шаг «фиша → одонтограмма» открывает вкладку перед
ссылкой и ждёт возврата на `?tab=odonto`. Старая страница (`?ui=legacy`) не
меняется. Сервер и API не меняются.

## Шаг 2 — один рабочий стол одонтограммы (26.09.2026)

Инструмент детальной страницы вынесен в `clinical/OdontogramWorkbench.tsx`
(дуга + инспектор, мосты, меню зуба, клавиатура C22, классы `.odop*`) и стоит в
двух местах: `/odontograma` (на всю ширину, сайдбар-рельс от сервера, обратная

разными возможностями на один зуб — лишняя развилка. Контейнер вкладки
держит прежние правила: модель из загрузчика фиши, свой запрос только без
засева, `?card=1(&views=1)` в записи зуба, свежая фиша наверх. Зуб из плана —
выбор в инспекторе и фокус на кнопке зуба (клавиатура готова сразу).
Тесты детальной (`OdontogramScreen.test.tsx`) не менялись — DOM тот же.

## Шаг 3 — пародонтограмма седьмой вкладкой (26.09.2026)

Лист вынесен в `clinical/PerioWorkbench.tsx` (чистый вид: дуги, ввод диктовкой,
итог, шапка с осмотрами); контроллер `usePerio` остаётся у ВЛАДЕЛЬЦА — черновик
обязан пережить смену осмотра, когда лист на миг снят. Владельцы двое: страница
`/parodontograma` (загрузчик роутера, `?exam=`, `leaving` через `pending`) и
`PerioTab` во вкладке (`?tab=perio&exam=`): загрузчик фиши осмотр не носит и не
должен (полный GET фиши = «Fișa deschisă»), поэтому вкладка грузит лист сама по
монтажу и при смене осмотра в адресе; `req` — осмотр, для которого модель на
экране, расхождение с адресом = загрузка (лист снят, как `leaving`). После POST
ответ уже на экране и `req` совпадает с новым адресом — второго GET нет. `examOf`
один, в `perio.ts`. Ссылка «Parodontogramă» из рабочего стола одонтограммы во
вкладке ведёт на соседнюю вкладку, со страницы — на страницу; «назад» со
страницы — `?tab=perio&exam=`. Тесты страницы (`PerioScreen.test.tsx`) не менялись.
