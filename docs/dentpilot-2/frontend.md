# Клиент — React + TypeScript + Vite

✅ **Каркас существует и собирается.** Живёт в `app/frontend/`.
Рабочие подробности (команды, ограничения сборки, ловушки) —
[../../frontend/README.md](../../frontend/README.md); здесь только решения.

## Почему одна папка, а не отдельный репозиторий

⭐ **Флаги требуют одного бинарника.** Переключение экрана флагом в
`clinic.json` происходит **без пересборки**, значит старый интерфейс и новый
лежат в одном `DentPilot.exe`. Два репозитория воюют ровно с этим — а откат без
пересборки и есть то, что делает переход безопасным.

Плюс: версия одна (`engine.py:22`), правка «эндпоинт + экран + переписанные
проверки» остаётся **одним** коммитом, а генератор карты экранов читает `bot/`
и `tests/` вместе.

## Структура

```
frontend/src/
  main.tsx        монтируется в #root, создаёт роутер (B2)
  app/            корень клиента: App.tsx (экраны и дерево маршрутов),
                  routes.ts — ПРОИЗВОДНАЯ таблица адресов (scripts/screen_map.py)
  services/       ЕДИНСТВЕННАЯ точка разговора с движком
  types/          конверт ответа и разбор отказов
  components/     переиспользуемые примитивы
  features/       по предметным областям
  layouts/ hooks/ stores/ utils/
```

⛔ Компоненты в сеть не ходят — только через `services/api.ts`. Иначе разбор
конверта, обработка истёкшей сессии и проверка прав расползутся по сорока
экранам и разойдутся между собой.

## Отдать ли React — решает сервер, какой экран — роутер

```html
<div id="root" data-screen="settings_clinic" data-params="…" data-shell="…"></div>
```

Узел — тот же рубильник, что и флаг в `clinic.json`: сервер решает, отдать
старую разметку или узел для React. Клиент про флаг ничего не знает.

С B2 (24.09) экран выбирает **роутер по адресу** (`createBrowserRouter`,
data-режим), а таблица адресов `app/routes.ts` генерируется из серверной карты
— своей в клиенте нет. `data-screen` остаётся свидетелем: разошёлся с роутером
— бандл и сервер из разных версий, и клиент говорит «экрана нет», а не рисует
чужой. Решение и ступени — [spa-transition.md](spa-transition.md).

## Состояние

Серверное состояние и состояние экрана — разные вещи.

| | Что | Чем |
|---|---|---|
| Серверное | данные пациентов, расписание, справочники | запросы + кеш |
| Экранное | выбранный зуб, открытый диалог, фильтр, вкладка | React state / context |

⏳ Библиотека управления состоянием **пока не добавлена и не нужна**: 41 экран,
состояние в основном серверное. Появится, когда появится причина, а не заранее.

## Оболочка не дублируется

Сайдбар, верхнюю панель, тему, шрифты, класс `anim`, PWA-шапку рисует серверный
`core/layout._shell`. React получает один узел внутри неё.

⛔ Мигрированный экран **никогда не лежит внутри `#live`**. Иначе `panel.js`
через 12 секунд подменит `innerHTML` под смонтированным деревом: карточка
перестанет открываться, перетаскивание умрёт, а в консоли будет пусто.
Правило проверяемое: на странице одновременно не существуют `#root` и `#live`.

## Кто владеет словами

Подписи экрана (заголовок, поля, кнопки, «движок не отвечает») живут в самом
экране — как у старой страницы они жили в её обработчике. Всё общее — коды и
тексты ответов, названия статусов — приходит из конверта и на клиенте не
переводится. Иконки — `components/icons.ts`, сгенерированный из `layout._I`
(`python scripts/gen_icons.py`); правка руками пропадёт при пересборке.

⚠️ С 21.09 у правила есть продолжение — `i18n.md` §3. Подписи по-прежнему
принадлежат экрану, но обязаны лежать ОДНИМ словарём в начале файла, а не
литералами по JSX: словарей уже 55, и переход на каталог — это одна строка в
каждом файле ровно потому, что строки собраны.
✅ Шов введён (`utils/i18n.ts`): словарь объявляется как
`const T = t('ns', { … } as const)`, обращения `T.save` не меняются ни одно, а
при отсутствующем каталоге отдаётся сам объект — диффа поведения ноль.
Последние четыре экрана (C9, C10, C15, C14+) написаны уже так.
⛔ Новый экран объявляет словарь через `t()`, а не литералами по разметке:
раскидать текст по JSX значит оплатить второй проход по этому экрану.
