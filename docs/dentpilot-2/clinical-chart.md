# Клинический модуль: одонтограмма и пародонтограмма в React

✅ **Контракт принят Олегом 18.09.2026** — после сверки с кодом, перед C21.
Менять его до конца C23 не предполагается.

## Формула

**Сервер владеет клинической истиной и геометрией. React владеет
композицией, интерактивом и UX.**

| Что | Где | Почему |
|---|---|---|
| Геометрия зуба (коронки, корни, поверхности, вид сверху, ореолы, зеркало по квадранту, переворот дуг) | `teeth_svg.py` | один источник на экран, печатную 043/e, лист пародонтограммы и выгрузку; десять наборов `test_teeth` стерегут канон; ⛔ второго движка геометрии на TypeScript не будет — «почему зуб 16 в PDF выглядит не так, как на экране» через год |
| Клинические правила (состояния, поверхности, отметки, мосты, PD = 0 «не измеряли», BOP%) | `db.py`, `odontogram.py`, `perio.py`, `routes.py` | те же функции, что у старых страниц и печати |
| Клиническая модель | `GET /api/patients/{pid}/odontogram`, `GET …/perio` | данные, не разметка |
| Композиция, выбор, наведение, поверхности, инспектор, мосты, ввод, история | React `features/clinical/` | всё, что в старых страницах было инлайновым JS |

## SVG зуба адресуем для клика

`tooth_svg`/`occlusal_svg` умеют по флагу `hit=True` дописать в рисунок
невидимые цели поверхностей `<g class='sfz'>` с `data-s` = M/O/D/V/L
(лицевой вид — по позициям меток `_surface_marks`, сверху — по зонам
`occ_zones`, обрезанным контуром). Они внутри той же зеркалящей обёртки, что
и рисунок, поэтому сторона правильная сама собой. React не знает геометрию
зуба, но знает, по какой поверхности кликнули: обработчик — делегированием на
`[data-s]`. Старые страницы флаг не просят и не меняются.

## Компонент `Tooth` — слои, не клинический объект

```
ToothModel (данные API)   →   ToothGeometry (SVG сервера)   →   Tooth
                                                                  ├── GeometryLayer      (innerHTML SVG)
                                                                  ├── SurfaceInteractionLayer (data-s)
                                                                  ├── ConditionLayer     (классы tooth-{state}, ореолы — в SVG)
                                                                  ├── SelectionLayer     (класс sel / br-pick)
                                                                  └── AnnotationLayer    (номер, подсказка)
```

Тот же `Tooth` — в одонтограмме (дуга, инспектор, компактная карточка фиши),
в пародонтограмме (под таблицей измерений), в плане и истории (ссылка на
зуб).

## Поверхности: ключи и подписи

Ключи данных не меняются: `M O D V L` (как в базе, 043/e и выгрузке).
Подпись на экране зависит от челюсти: **верхняя — `M O D V P`, нижняя —
`M O D V L`**; подсказка — полное слово (V — vestibulară, P — palatinală,
L — linguală; по-русски вестибулярная / нёбная / язычная). Решение Олега
18.09: в румынской терминологии для верхних зубов естественно «palatinal».

## Один зуб на оба инструмента — на уровне API

Одонтограмма ключуется по зубу (`teeth`), пародонтограмма — по датированному
ОСМОТРУ (`perio_exams` + `perio_teeth`), и так остаётся: карта пародонта
живёт сравнением во времени. «Зуб 16 — один объект» собирает API: инспектор
одонтограммы показывает строку последнего осмотра по зубу, клетки
пародонтограммы знают состояние зуба (отсутствующие — приглушены).

## Этапы

- **C21 — фундамент:** пин старых страниц (`test_odontogram_api.suite_pin`),
  `hit=True` в SVG, `GET /api/patients/{pid}/odontogram` и действия
  (`POST …/teeth/{n}` с явными полями намерения, `POST …/bridges`,
  `POST …/bridges/{id}/delete`), React `ClinicalChart`: дуга, `Tooth`,
  выбор, инспектор с нынешними полями, история зуба, режим моста со скобкой
  (измерение через refs, не `offsetLeft` из скрипта), переключатель вида,
  молочные, легенда. **Компактная карточка фиши** становится тем же
  компонентом и закрывает точку интеграции C18 (`GET …/teeth` с HTML
  уходит). Флаг `odontogram`.
- **C22 — UX:** клик по поверхности как первичный жест, клавиатура,
  контекстные действия, отзывчивость, кадры headless Edge. Только после
  зелёного C21.
- **C23 — пародонтограмма:** API осмотров и сводки (считает сервер), React
  таблица измерений с диктовкой цифр (самое дорогое — ввод ~200 чисел, не
  рисунок), тот же `Tooth` под таблицей, сравнение осмотров. Печатный лист
  остаётся серверным.

## Чего в C21–C23 нет намеренно

Нумерации Universal/Palmer (в данных только FDI — новая функция, не
перенос), 3D и реалистичный вид, рентген-оверлей, undo/redo сверх летописи и
`state0`, мультивыбор и массовые действия, линейка, экспорт PNG/SVG. Шесть
capabilities с макета — контракт компонента (слои `Tooth`, состояния
данными), а не список работ этапа. Правило Олега: миграцию не смешивать с
редизайном, красивый UI — отдельно, после.

## Прайоры, которые здесь ломаются молча

- Намерение формы — явным полем (`state0`, карта поверхностей или `null`,
  отметки или `null`): две потери данных 08-16; повторный POST того же тела
  тождествен строке в базе.
- `PD = 0` — «не измеряли»; BOP% и средняя глубина — только сервером.
- Ничего графического от Windows: значки — `Icon` из `layout._I`.
- Печатные листы обновление не меняет: клетка 043/e мигрированного зуба
  выглядит как до обновления.
- Скобка моста меряется по кнопкам ВИДИМОЙ дуги после раскладки; `--arc`
  вида сверху двигает зуб transform-ом, который `offsetTop` не видит.
