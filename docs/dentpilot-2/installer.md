# Установщик

⚠️ **Читать вместе с [storage.md](storage.md).** 20.09 Олег решил, что
`Program Files` — целевая архитектура, а данные уезжают в `ProgramData`. Три
пункта ниже — «запрет установки в `Program Files`», «путь по умолчанию
`C:\Users\Public\DentPilot`» и «данные клиники остались» при удалении — после
блока P меняются. Всё остальное на этой странице в силе.

✅ **Работает сегодня и остаётся.** Inno Setup 6, `installer/DentPilot.iss`.

```
tauri build --bundles none
        ↓
   DentPilot.exe
        ↓
    Inno Setup
        ↓
DentPilot-Setup-X.Y.Z.exe
```

⛔ **NSIS автоматически не брать.** Tauri умеет отдать просто папку с exe, и
тогда переживают все 152 строки Pascal-логики, которые уже написаны и проверены.

## Что именно переживает

- запрет установки в `Program Files`;
- проба записи в целевую папку;
- путь по умолчанию `C:\Users\Public\DentPilot`;
- две ветки установки WebView2 Runtime;
- окно «данные клиники остались» при удалении;
- фиксированный AppId;
- румынский мастер установки.

## Почему не штатный бандл Tauri

⛔ Штатный NSIS ставит **per-user**, обычно под `%LOCALAPPDATA%`. Данные клиники
лежат **рядом с exe**: `clinic.json`, `dental.env`, `data\dental.db`,
`data\backups\` (14 копий), `data\files\` (все снимки и документы пациентов).

В клинике две смены — это две учётные записи Windows. Вторая смена откроет
программу и увидит **пустой журнал при живой базе**.

⛔ И второе: NSIS при обновлении по умолчанию запускает деинсталлятор прежней
версии, а тот чистит папку установки. В `DentPilot.iss` удаление перечислено
**поимённо**, и ни одна запись не трогает данные.

## Обязательная приёмочная проверка

```
чистая Windows
      ↓
поставить версию N
      ↓
завести пациента
      ↓
закрыть
      ↓
поставить N+1 ПОВЕРХ
      ↓
запустить
      ↓
пациент на месте?
```

Если данные исчезли — **выпуск запрещён**.

⚠️ Апгрейд не равен чистой установке: данные переживают установщик по замыслу,
поэтому поведение «как у новой клиники» проверять только в пустой папке.

## Подпись

✅ **Конвейер готов с 26.09; ждёт сертификата.** Пока переменной
`DENTPILOT_SIGN_THUMBPRINT` нет, `Build-Installer.ps1` собирает как раньше и
громко пишет «BEZ PODPISI». Есть — подписывает, а упавшая подпись
останавливает сборку.

**Как включить (один раз, когда придёт сертификат):**

1. Купить **Certum Cloud Code Signing for Individual Developer** (реселлер
   SSLmentor, ~$139/год; 3 года дешевле за год). Документы: паспорт или ID,
   счёт за коммунальные услуги с адресом, онлайн-проверка лица; 2–4 рабочих
   дня. Молдову принимают. ⚠️ С 27.02.2026 один сертификат живёт не дольше
   459 дней — многолетняя покупка = перевыпуск раз в ~15 месяцев.
2. Поставить **SimplySign** на телефон и **SimplySign Desktop** на ПК сборки;
   войти — сертификат появится в `Cert:\CurrentUser\My` (закрытый ключ
   остаётся в облаке Certum, выгрузить его нельзя, 5 000 подписей в месяц).
3. Отпечаток сертификата — в постоянную переменную пользователя (он не
   секрет): `[Environment]::SetEnvironmentVariable("DENTPILOT_SIGN_THUMBPRINT",
   "<отпечаток>", "User")`; найти его — `Get-ChildItem Cert:\CurrentUser\My
   -CodeSigningCert`.
4. **Перед каждой сборкой** войти в SimplySign Desktop (код из приложения на
   телефоне) — иначе ключ недоступен и `Sign-File.ps1` остановит сборку.
5. Сверить имя: в индивидуальном сертификате — **личное** имя («Oleg
   Bacalu»), а издатель в свойствах файла и в «Установленных приложениях» —
   «A.I. Oleg Bacalu» (`sync_version.COMPANY` + `AppPublisher`). Привести к
   имени сертификата одной правкой в двух местах (сверку держит
   `sync_version --check`), иначе UAC и список программ назовут поставщика
   по-разному.

**Что делает конвейер** (`Sign-File.ps1`, вызывают `Build-Installer.ps1` и Inno):

1. `dist\DentPilot.exe` — **первым**, сразу после PyInstaller и до дымового
   теста, чтобы проверялся тот файл, который поедет клинике;
2. `dist\DentPilot-Setup-X.Y.Z.exe` и деинсталлятор — подписывает сам Inno той
   же командой (`/DSignTool` + `/Sdpsign=…`, в `.iss` — `SignTool=dpsign` и
   `SignedUninstaller=yes` под `#ifdef SignTool`), после чего сборка сверяет,
   что подпись мастера `Valid`.

Каждая подпись — SHA256 и **метка времени** Certum (`http://time.certum.pl`):
без неё подпись умерла бы вместе со сроком сертификата, задним числом у всех
клиник. После подписи `Sign-File.ps1` проверяет: подписан именно этим
сертификатом, метка времени есть, статус `Valid` — иначе код выхода 1.
Инструмент — `signtool`, если стоит Windows SDK, иначе встроенный
`Set-AuthenticodeSignature` (SDK на ПК сборки нет — и не нужен).
⚠️ Встроенный путь при недоступном сервере меток подписывает МОЛЧА без метки —
ловит это только проверка после подписи (испытано).

**Испытано 26.09 одноразовым самоподписанным сертификатом** (PFX из
`openssl`, в хранилище Windows не клался): копия `DentPilot.exe` 1.35.0 и
полный `ISCC` установщика — Inno сам вызвал подпись для деинсталлятора и для
мастера, метка «Certum Timestamp 2026» на обоих; статус `UnknownError` — корень
одноразового сертификата Windows не знает, у настоящего будет `Valid`. Отказы
тоже проверены: недоверенная подпись, отпечатка нет в хранилище, отпечаток не
задан, сервер меток недоступен — каждый код выхода 1. Порядок держит
`test_guards.suite_signing` («Выпуск: подпись…»), с порчами, на которых обязан
краснеть. Сама подпись в прогоне не делается — сертификата там нет.

⛔ Подписать **только установщик** — худший вариант: обновление в один клик
скачивает `DentPilot.exe` напрямую, и первая же самообновка молча вернёт
клинику к неподписанному файлу. Заметить нельзя — при самообновлении SmartScreen
не показывается вовсе (файл скачан не браузером, метки Mark-of-the-Web нет).

Третий файл, о котором забывают: `unins000.exe`. Лечится директивами `SignTool`
и `SignedUninstaller` в `.iss`.

⚠️ Подпись меняет байты, а значит и sha256. Подписывать **до** заливки ассета.

⚠️ Сертификат уровня OV/EV выдаётся организации и проверяется по реестру;
IDNO антрепренора есть с 23.09. Индивидуальный сертификат (самый доступный —
Certum Cloud Code Signing для индивидуальных разработчиков, в облаке SimplySign,
без токена) несёт ЛИЧНОЕ имя — и именно его покажет окно UAC. Какое имя будет в
сертификате — сверить до покупки: с ним должен совпасть издатель ниже, иначе
UAC и «Установленные приложения» назовут поставщика по-разному.

⚠️ «Издатель: неизвестно» в UAC и SmartScreen убирает ТОЛЬКО подпись: Windows
намеренно не читает имя, которое файл пишет о себе сам. У свежего сертификата
SmartScreen ещё какое-то время предупреждает (репутация копится скачиваниями),
но уже с именем издателя.

## Метаданные файла

✅ Поля свойств заполняет `scripts/sync_version.py`: он генерирует ресурс для
флага `--version-file` у PyInstaller из `APP_VERSION` (`Build-Desktop.ps1`
зовёт его первым шагом). Сертификата это не требует.

**Издатель — «A.I. Oleg Bacalu»** (решение Олега 26.09; до того «DentPilot»):
`CompanyName` и `LegalCopyright` у exe (`sync_version.COMPANY`) и
`AppPublisher` / `VersionInfoCompany` / `VersionInfoCopyright` у установщика
(`installer/DentPilot.iss`). Имя живёт в двух файлах, поэтому
`sync_version --check` (и прогон, набор «Выпуск: версия одна…») сверяет их и
краснеет на расхождении. ⚠️ У клиник, обновляющихся изнутри программы, строка
«Издатель» в «Установленных приложениях» сменится только при следующем запуске
установщика: обновление в один клик подменяет exe, а запись реестра правит
лишь `DisplayVersion` (`privileged.py`). Свойства самого exe меняются с первым
же обновлением.
