## Сборка

```
frontend/ (vite) + bot/ ── Build-Engine.ps1 ──→ dist\DentPilot-Engine\      PyInstaller папкой;
                                                                        стенд engine_check --exe
shell/ ── cargo build --release --locked ──→ shell\target\release\DentPilot.exe
                         ↓
       dist\DentPilot\ = DentPilot.exe + engine\          ← подпись ОБОИХ exe
                         ↓
       scripts\shell_check.py — оболочка поднимает движок (22 проверки)
                         ↓
       Inno Setup → dist\DentPilot-Setup-X.Y.Z.exe        ← подпись мастера и деинсталлятора
                         ↓
       dist\DentPilot-Setup-X.Y.Z.zip — ЕДИНСТВЕННЫЙ ассет выпуска (release.py)
```

```powershell
powershell -File Build-Installer.ps1            # выпускная: чистое дерево, всё запушено, ПОДПИСЬ
powershell -File Build-Installer.ps1 -NoSign    # пробная: без подписи, дерево может быть грязным
powershell -File Build-Installer.ps1 -SkipApp   # перепаковать готовую dist\DentPilot (правка .iss)
powershell -File Build-Installer.ps1 -SetupDir D:\DentProject\sandbox\handout   # копия мастера — не в releases\
```

⚠️ Выпускная сборка кладёт копию мастера в `D:\DentProject\releases` (то,
что отдают клиникам), а прошлую уводит в `arhiva\`. Подписанную пробу —
только с `-SetupDir <папка-песочница>`: пустая строка `-SetupDir ""` через
`powershell -File` теряется (PowerShell 5.1 не передаёт пустой аргумент), и
сборка падает «Missing an argument» — безопасно, но не то.

- **Нужно на ПК сборки**: Rust (`D:\Rust`: cargo, rustup; Build Tools — на
  D:, их находит сам cargo), `.venv-desktop` (движок, и им же `shell/assets.py`
  рисует заставку и значок оболочки), npm (клиент), Inno Setup 6. Приложение
  Claude и старое окно терминала переменных пользователя не видят — поэтому
  сборка берёт cargo явным путём `D:\Rust\cargo\bin\cargo.exe` (или
  `DENTPILOT_CARGO`), `CARGO_HOME`/`RUSTUP_HOME` — рядом с ним, `TMP` cargo — в
  `D:\Rust\_tmp`, сборку оболочки — в `shell\target` (в git не едет).
- **Выпускная сборка без подписи не идёт**: нет отпечатка или ключ недоступен —
  стоп (до Т9 шла дальше одной жёлтой строкой «BEZ PODPISI»). Пробная `-NoSign`
  в `D:\DentProject\releases` не кладётся, а `release.py prerelease` проверяет
  подпись мастера сам — тем же, чем проверит программа клиники
  (`privileged.SIGNERS`), — и неподписанный не зальёт.
- **Версия одна** — `APP_VERSION` в `bot/app/engine.py`. Движок — через
  `sync_version.py` (свойства exe) и `/health`; оболочка — `shell/build.rs`
  (свойства `DentPilot.exe` и `dpShell.version`); мастер — `/DAppVersion=` из
  того, что СОБРАННАЯ программа сказала о себе под оболочкой. Стенд сверяет
  все четыре, сборка — ещё и с `engine.py`. Второго источника нет.
  ✅ Опыт 18.10: временный бамп `APP_VERSION` до 2.0.0 (без коммита) — без
  единой правки в `shell/` и `.iss` сборка дала `/health` 2.0.0, свойства
  обоих exe 2.0.0, `dpShell.version` 2.0.0, мастер `DentPilot-Setup-2.0.0.exe`
  с версией файла 2.0.0.0. Подложенная в ту же папку оболочка 1.46.1 —
  стоп: «получено '1.46.1', ожидалось '2.0.0'» у свойств и у `dpShell`.
- **Стенд пары** `scripts/shell_check.py` (дымовой тест сборки): папка
  программы копируется во временную «установку» (`build\smoke`, на диске
  репозитория), оболочка `--tray` (окна нет) поднимает движок из `engine\` в
  своём задании; `/health`, `dpShell` v1 на странице (порт отладки WebView2),
  обход страниц `smoke_exe.py` (свежая установка — `wall`, живая картотека —
  `grace`), второй запуск уходит сам, честный выход путём человека (вопрос
  оболочки «Închideți DentPilot complet?» — стенд нажимает «Да» по PID своей
  оболочки, окно мелькает на экране), снятие оболочки гасит движок. Процессы —
  только по PID: имя `DentPilot.exe` у установленной программы то же.
- **Состав мастера** — без запуска, по журналу ISCC (`dist\iscc.log`, строки
  `Compressing:`): каждый файл `dist\DentPilot` внутри, и ничего, кроме него,
  `demo.flag` и загрузчика WebView2. ⚠️ У файла без `ignoreversion` ISCC
  дописывает версию: `…Setup.exe   (1.3.251.23)` — разбор её снимает.

⛔ **Мастер на машине сборки не запускается** — ни тихо, ни с окном: здесь
стоит установленная программа Олега (`C:\Program Files\DentPilot`, данные
`C:\ProgramData\DentPilot`, порт 8088), и тот же AppId обновил бы её.
Поведение Inno, которое нельзя увидеть без запуска, проверено одноразовым
мини-мастером (свой AppId, без прав, в песочницу) — ниже.

## Что ставит мастер

```
{app} = C:\Program Files\DentPilot
  DentPilot.exe                  оболочка — её знают ярлыки, сторож, «Программы и компоненты»
  engine\DentPilot-Engine.exe    движок
  engine\_internal\…             PyInstaller папкой (всего 729 файлов, 62,9 МБ)
  install.json, demo.flag        корень программы (BASE) — папка DentPilot.exe, не engine\
{commonappdata}\DentPilot        данные клиники, права users-modify (как с P3-min)
```

- **`[InstallDelete]` сносит `{app}\engine` перед копированием**: у новой версии
  другой набор файлов в `_internal\`, а Inno только добавляет и заменяет. В
  папке движка данных нет никогда.
- **Ярлыки «Пуска» и рабочего стола несут `AppUserModelID: "md.dentpilot.app"`**
  — тот же, что `identifier` оболочки (`shell/tauri.conf.json`; сверяет
  `test_installer.suite_tauri_layout`). Без ярлыка с этим паспортом Windows
  уведомления оболочки показывает только в истории, без баннера (опыт Т6).
  ✅ Опыт 18.10 (мини-мастер): Inno пишет `System.AppUserModel.ID` в ярлык.
- **WebView2 обязателен**: без него окно оболочки не создаётся вовсе (у окна
  pywebview был запасной путь «в браузер», у Tauri — нет; окно и запасной
  браузер сняты 22.10.2026). Ставят его строки
  `[Run]` (флешка → бутстрэппер, как раньше), а после них `CurStepChanged
  (ssPostInstall)` проверяет, встал ли он, и говорит словами (`NoWebView2Text`,
  гасится тихим режимом). Установка при отказе не валится: файлы уже на месте,
  повторный запуск мастера с интернетом доставит Runtime.
  ✅ Опыт 18.10 (мини-мастер): неотложенные `[Run]` идут ДО `ssPostInstall`.
- **Файлы программы мастер получает свободными** — раздел ниже.
- **Удаление**: файлы программы и папка `engine\` целиком; данные в
  `{commonappdata}` остаются (окно `DataKeptText`). `{app}` целиком не сносится:
  папку выбирает человек. `%LOCALAPPDATA%\DentPilot` (профиль окна, `shell.json`,
  `shell.log`) — по учётке Windows, деинсталлятор от администратора чужих
  профилей не видит; остаётся, как оставался профиль окна pywebview.
- **Поверх прежней сборки одним файлом (1.x)**: AppId и имя `DentPilot.exe` те
  же — Inno заменяет onefile оболочкой и добавляет `engine\`. Проверяет Т11.

## Как мастер освобождает `DentPilot.exe` и `engine\`

Заменить файлы, которые держит живой процесс, Inno не может: `DentPilot.exe`
держит оболочка, `engine\DentPilot-Engine.exe`, `python*.dll` и `*.pyd` —
движок. Освобождают их три шага по очереди, каждый — страховка следующего:

1. **Программа уходит сама** (путь обновления, Т10): движок говорит оболочке
   `quit`, оболочка закрывается без вопроса и останавливает движок словом
   (≤ 10 с, потом снимает его задание); привилегированный движок, запустивший
   мастер за UAC, выходит сразу за ним. Сторож обновления — копия оболочки в
   `ProgramData\DentPilot\updates\DentPilot-watch.exe` — живёт ВНЕ `{app}` и
   ничего там не держит; копия самого мастера лежит в `{app}\updates\`, и
   `[InstallDelete]` её не трогает.
2. **`PrepareToInstall` ждёт обоих** — только при `/RESULT=` (тихое
   обновление; у человека за мастером это выглядело бы зависанием):
   `AppProcessCount` считает процессы по ПУТИ — `{app}\DentPilot.exe` и
   `{app}\engine\DentPilot-Engine.exe` (WMI, `ExecutablePath`; копии в других
   папках не в счёт), опрос раз в 250 мс, потолок 30 с по часам
   (`GetTickCount`). Ждать нужно потому, что Restart Manager, заставший
   уходящий процесс, проигрывает гонку и тихий мастер отвечает Abort
   (канарейка 1.41.2, 12.10). `AppMutex` нет намеренно: найденный мьютекс в
   тихом режиме = отказ, а старая оболочка гаснет ~1 с после «started».
3. **Restart Manager** (`CloseApplications=yes`, обновление передаёт
   `/CLOSEAPPLICATIONS /FORCECLOSEAPPLICATIONS`) — для того, что не ушло: окно
   под другой учёткой, ручная установка поверх открытой программы. Он находит
   процессы по файлам (`*.exe`, `*.dll` — 17 файлов программы, этого хватает
   и на оболочку, и на движок) и закрывает их. Оболочке приходит
   `WM_QUERYENDSESSION`/`WM_ENDSESSION`: tao зовёт `exit(0)`, но перед этим
   отдаёт событие выхода, и наш выход проходит целиком — движок остановлен
   словом, база закрыта.

Только после этого `[InstallDelete]` сносит `engine\`, и `[Files]` кладут
новую версию.

✅ **Опыт 18.10.** Одноразовый мини-мастер (свой AppId, без прав, в
лабораторию) с теми же `[InstallDelete]`, функциями ожидания и `/RESULT=`, что
`DentPilot.iss` (берёт их текстом из него), и ключами обновления
(`privileged.SETUP_FLAGS`) — поверх ЖИВОЙ подписанной пары:

| Сценарий | Что в журнале мастера | Итог |
|---|---|---|
| оболочка закрыта прямо перед мастером (путь Т10) | Restart Manager: никого | «ok» за 5,9–7,0 с |
| закрыта через 3 с после старта мастера | «Zhdem vyhoda… processov 2» → «otpushcheny cherez 2406 ms» → RM: никого | «ok» |
| не закрывается вовсе (`/RESULT=`) | ждали ровно 30 с → RM нашёл обе части, «Shutting down (forced)» | «ok» за 35,9 с |
| ручная установка поверх открытой (без `/RESULT=`) | RM нашёл «DentPilot» и «DentPilot — registrul clinicii…», закрыл | код 0 за 4,7 с |

Во всех четырёх: оболочка вышла с кодом 0, в её журнале «engine stopped in
0.2 s, code Some(0)», в журнале движка — остановка по слову, `-wal` сброшен,
и после установки программа снова поднялась (`/health`). Мастер с правами
администратора и вторая учётка Windows так не проверены — это Т11.

## Почему не штатный бандл Tauri

⛔ **NSIS/MSI Tauri не брать** (`bundle.active: false` в `tauri.conf.json`,
сборка — `cargo build`, раскладку собирает `Build-Installer.ps1`). В `.iss`
уже прожито и проверено живьём то, чего у штатного бандла нет:

- per-machine установка в Program Files и данные в ProgramData с правами для
  всех учёток (две смены = две учётки Windows; per-user NSIS дал бы второй
  смене пустой журнал при живой базе);
- тот же AppId, что у всех выпусков 1.x, — установка поверх, а не рядом;
- протокол тихого обновления (`/RESULT=`, ожидание процессов, `CHANNEL=`);
- блокировка поверх старой раскладки «данные рядом с exe»;
- две ветки WebView2 (флешка без интернета и бутстрэппер), румынский мастер;
- удаление поимённо: ни одна запись не трогает данные (NSIS при обновлении
  по умолчанию запускает деинсталлятор прежней версии).

## Обязательная приёмочная проверка

```
чистая Windows
      ↓
поставить версию N
      ↓
завести пациента
      ↓
закрыть
      ↓
поставить N+1 ПОВЕРХ
      ↓
запустить
      ↓
пациент на месте?
```

Если данные исчезли — **выпуск запрещён**.

⚠️ Апгрейд не равен чистой установке: данные переживают установщик по замыслу,
поэтому поведение «как у новой клиники» проверять только в пустой папке.

Для Tauri (Т11) вдобавок: в «Диспетчере задач» два процесса (`DentPilot.exe`
и `DentPilot-Engine.exe`), после выхода — ни одного; уведомление показывается
баннером у часов (ярлык с паспортом); поверх 1.46.x (onefile) — `engine\`
появилась, прежний `DentPilot.exe` заменён оболочкой, пациент на месте;
удаление оставляет `C:\ProgramData\DentPilot`.

⭐ Окно, профиль и вход (08.10): до 22.10.2026 их гонял стенд окна pywebview
(`.\dev bench launcher`: PIN → фиша → закрыть → старт без входа → второй
запуск фокусирует первое окно → выход → экран входа; и общий ПК); снят вместе
с окном. Пару «оболочка + движок» гоняет `scripts/shell_check.py` в
`Build-Installer.ps1`; вход и второй запуск у собранной пары — шаги
проверки руками выше. Разбор — `deployment-modes.md` › «Окно программы».

**Как включить** (сделано 29.09; повторить на новом ПК сборки и после
перевыпуска — отпечаток у нового сертификата другой):

1. Сертификат — **Certum Cloud Code Signing for Individual Developer** у
   реселлера SSLmentor. Проверка: IDnow с телефона по ОРИГИНАЛУ документа
   (копии и сканы отклоняются) + счёт за коммунальные услуги на своё имя —

   покупка = перевыпуск раз в ~15 месяцев.
2. **SimplySign** на телефон (режим «Generate token»: телефон только выдаёт
   одноразовые коды входа, подпись идёт на ПК) и **SimplySign Desktop** на ПК
   сборки; войти — сертификат появится в `Cert:\CurrentUser\My` (закрытый ключ

3. Отпечаток сертификата — в постоянную переменную пользователя (он не

4. **Перед каждой сборкой** войти в SimplySign Desktop (код из приложения на
   телефоне) — иначе ключ недоступен и `Sign-File.ps1` остановит сборку. Вход
   держится около двух часов.
5. Сверить имя: в индивидуальном сертификате — **личное** имя («Oleg
   Bacalu»), а издатель в свойствах файла и в «Установленных приложениях» —
   «A.I. Oleg Bacalu» (`sync_version.COMPANY` + `AppPublisher`). Привести к
   имени сертификата одной правкой в двух местах (сверку держит
   `sync_version --check`), иначе UAC и список программ назовут поставщика
   по-разному.

**Что делает конвейер** (`Sign-File.ps1`, вызывают `Build-Installer.ps1` и Inno):

1. `dist\DentPilot\DentPilot.exe` (оболочка) и
   `dist\DentPilot\engine\DentPilot-Engine.exe` (движок) — сразу после сборки
   и до стенда пары, чтобы проверялось то, что поедет клинике;
2. `dist\DentPilot-Setup-X.Y.Z.exe` и деинсталлятор — подписывает сам Inno той
   же командой (`/DSignTool` + `/Sdpsign=…`, в `.iss` — `SignTool=dpsign` и
   `SignedUninstaller=yes` под `#ifdef SignTool`), после чего сборка сверяет,
   что подпись мастера `Valid`.

Каждая подпись — SHA256 и **метка времени** Certum (`http://time.certum.pl`):
без неё подпись умерла бы вместе со сроком сертификата, задним числом у всех
клиник. После подписи `Sign-File.ps1` проверяет: подписан именно этим
сертификатом, метка времени есть, статус `Valid` — иначе код выхода 1.
Инструмент — `signtool`, если стоит Windows SDK, иначе встроенный
`Set-AuthenticodeSignature` (SDK на ПК сборки нет — и не нужен).
⚠️ Встроенный путь при недоступном сервере меток подписывает МОЛЧА без метки —
ловит это только проверка после подписи (испытано).

**Испытано 26.09 одноразовым самоподписанным сертификатом** (PFX из
`openssl`, в хранилище Windows не клался): копия `DentPilot.exe` 1.35.0 и
полный `ISCC` установщика — Inno сам вызвал подпись для деинсталлятора и для
мастера, метка «Certum Timestamp 2026» на обоих; статус `UnknownError` — корень
одноразового сертификата Windows не знает, у настоящего будет `Valid`. Отказы
тоже проверены: недоверенная подпись, отпечатка нет в хранилище, отпечаток не
задан, сервер меток недоступен — каждый код выхода 1. Порядок держит
`test_guards.suite_signing` («Выпуск: подпись…»), с порчами, на которых обязан
краснеть. Сама подпись в прогоне не делается — сертификата там нет.
**29.09 — настоящим сертификатом:** `Sign-File.ps1` подписал копию
`DentPilot.exe` 1.35.2 — статус `Valid`, метка «Certum Timestamp 2026»,
цепочка до `Certum Trusted Network CA 2`; вторая копия — без `-Thumbprint`, из
окна, не видевшего переменную (отпечаток взят из реестра). Полная сборка с
Inno — 18.10 (Т9, пробная выпускная из `tauri/installer`): итог — три строки
«podpis …» (оболочка, движок, мастер) с `CN=Oleg Bacalu`, деинсталлятор
подписан тем же вызовом Inno; выпускная без подписи останавливается сама.

⛔ Подписать **только установщик** — плохо и с Tauri, хотя обновление теперь
идёт мастером: exe внутри видит не SmartScreen, а другие. Окно брандмауэра
«Разрешить доступ» — про ДВИЖОК (сеть слушает он, `lan.py` и `netcheck`
смотрят `sys.executable` = `engine\DentPilot-Engine.exe`); UAC
привилегированной операции (`privileged.py` поднимает тот же
`sys.executable`) называет издателя только по подписи файла; неподписанный
загрузчик PyInstaller антивирусы любят меньше; «Свойства» без подписи —
«неизвестный издатель». Заметить нельзя: у установленного exe нет метки
Mark-of-the-Web, SmartScreen его не спрашивает.

Третий файл, о котором забывают: `unins000.exe`. Лечится директивами `SignTool`
и `SignedUninstaller` в `.iss`.

⚠️ Подпись меняет байты, а значит и sha256. Подписывать **до** заливки ассета.

⚠️ Сертификат уровня OV/EV выдаётся организации и проверяется по реестру;
IDNO антрепренора есть с 23.09. Индивидуальный сертификат (самый доступный —
Certum Cloud Code Signing для индивидуальных разработчиков, в облаке SimplySign,
без токена) несёт ЛИЧНОЕ имя — и именно его покажет окно UAC. Какое имя будет в
сертификате — сверить до покупки: с ним должен совпасть издатель ниже, иначе
UAC и «Установленные приложения» назовут поставщика по-разному.

⚠️ «Издатель: неизвестно» в UAC и SmartScreen убирает ТОЛЬКО подпись: Windows
намеренно не читает имя, которое файл пишет о себе сам. У свежего сертификата
SmartScreen ещё какое-то время предупреждает (репутация копится скачиваниями),
но уже с именем издателя.

## Метаданные файла

✅ Поля свойств движка заполняет `scripts/sync_version.py`: он генерирует
ресурс для флага `--version-file` у PyInstaller из `APP_VERSION`
(`Build-Engine.ps1` зовёт его до PyInstaller). ⚠️ Ресурс
у движка тот же, что был у программы одним файлом: `OriginalFilename =
DentPilot.exe`, описание программы — движок отличается по имени файла. У
оболочки свойства пишет `tauri-build`: издатель и копирайт —
`tauri.conf.json`, версия — `APP_VERSION` (`shell/build.rs`). Сертификата это
не требует.

**Издатель — «A.I. Oleg Bacalu»** (решение Олега 26.09; до того «DentPilot»):
`CompanyName` и `LegalCopyright` у exe (`sync_version.COMPANY`) и
`AppPublisher` / `VersionInfoCompany` / `VersionInfoCopyright` у установщика
(`installer/DentPilot.iss`). Имя живёт в двух файлах, поэтому
`sync_version --check` (и прогон, набор «Выпуск: версия одна…») сверяет их и
краснеет на расхождении. С Т9 обновление идёт мастером, и запись в
«Установленных приложениях» (издатель, версия, значок) переписывает он
целиком. (До того подмена exe правила лишь `DisplayVersion`, `privileged.py`.)
