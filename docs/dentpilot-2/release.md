# Выпуск

Подробная процедура — [../../RELEASE.md](../../RELEASE.md). Здесь только то, что
меняется в DentPilot 2.0, и то, что ломает выпуск.

## Лестница — не меняется

```
поднять APP_VERSION → запушить → собрать → pre-release → канарейка → publish
```

⛔ **Publish только по слову Олега, на каждый выпуск.** CI имеет право доводить
дело до pre-release и **ни на шаг дальше**.

⛔ **Тег создаёт git, а не форма релиза.** Иначе тег новый, а exe внутри старый
— ловушка вечного цикла обновления.

⛔ **Тег отправлять поимённо**, никогда `--tags`: у репозитория лежат старые
локальные теги **без «v»**, и `--tags` утащит их на origin заодно. Так уже
уезжал тег на чужой коммит.

⛔ **Сборка идёт ДО тега**, намеренно. Триггер «по пушу тега» меняет порядок на
обратный, и упавшая сборка оставляет висящий тег.

⛔ **Релизы только вперёд:** не удалять, не снимать с публикации, не
перевешивать `latest`. Плохая сборка чинится выпуском следующей.

## Ворота — их двое, а не одни

**`tests/smoke_exe.py`** — вшит в `Build-Installer.ps1`, поднимает собранный exe
и спрашивает его страницы. Ловит забытый `--add-data` и потерянный
`--hidden-import`.

**`scripts/check_slot_guard.py`** — 416 строк, обязателен по `RELEASE.md`, если
правка тронула миграции (`MIGRATIONS_*`, `SCHEMA_VERSION`, слотовые индексы).
Делает копию живой базы, приводит её к состоянию «клиника до обновления»,
вносит конфликт двойной брони и запускает **собранный exe**, измеряя защиту
**поведением** (пробная вставка и откат), а не текстом индекса.

⭐ Он закрывает класс отказа «после обновления программа не открывается» —
ровно тот, что уже стоил одного выпуска. ⛔ Не обходить ради упрощения CI.

## Состав релиза

Ровно два ассета: `DentPilot.exe` и `DentPilot-Setup-X.Y.Z.zip`.

⚠️ Установщик уезжает **архивом**, потому что правило обновлятора — «ровно один
`.exe`, и он называется `DentPilot.exe`». Гейты в `release.py` и
`check_release.py` это стерегут.

⛔ Ослаблять гейты нельзя. Если состав меняется — править клиент и **оба**
скрипта одним заходом и сразу прогонять `prerelease` на тестовом релизе.

⛔ Веб-формой релизы не трогать: три ловушки за два дня (тег без «v», молчаливое
несохранение, черновик-двойник при Publish).

## Версия — один источник

`bot/app/engine.py` — источник истины. Синхронизировать: `package.json`,
`tauri.conf.json`, `Cargo.toml`, тег, GitHub Release, имя ассета.

⏳ Завести `scripts/sync_version.py --check` и звать его в трёх местах:
`.\dev check`, первый шаг workflow, отдельное правило в `test_structure.py`.

⚠️ Разъехавшаяся версия = **вечный цикл обновления** у клиники: обновлятор
видит версию новее своей после каждой установки.

## CI — ступенями

| | Что | Состояние |
|---|---|---|
| **1** | прогон движка на каждый push и PR | ✅ файл есть, на GitHub ещё не исполнялся |
| **2** | typecheck, тесты и сборка фронта | ⏳ когда появится первый экран |
| **3** | сборка Tauri, отдельной задачей | ⏳ |
| **4** | дымовой тест собранного, E2E, артефакты | ⏳ |
| **5** | pre-release | ⏳ publish остаётся ручным |

⚠️ Не заставлять обычную разработку платить холодной сборкой Rust.

### Секреты

⛔ `DENTART_UPDATE_TOKEN` в Actions **не класть вообще** — это прямой канал
«обновление в один клик» во все установленные клиники. Достаточно встроенного
токена задачи с правом записи, который живёт минуты.

⛔ Подписывать **локально, не в CI.** С аппаратным токеном это физически
невозможно, а с облачным ключом утечка означает отзыв сертификата, после
которого **все уже выпущенные сборки становятся отозванными** — красное окно
«издатель отозван» хуже нынешнего синего.

⛔ Сторонние Actions пришпиливать по SHA коммита, а не по тегу: тег
перевешивается, SHA — нет.

## Ошибка измерения, которую легко повторить

⚠️ Прогон через конвейер (`… | tail`) **теряет код выхода**: в bash код
принадлежит последней команде конвейера. Харнесс исправен — `run()` возвращает
1 при любой неудаче, — но проверять надо без пайпа. В workflow пайпа нет.

⚠️ Отдельно: под тяжёлой дисковой нагрузкой миграционные наборы могут упасть с
`disk I/O error`. Ретрай в CI **не добавлять** — он маскировал бы настоящие
падения.
