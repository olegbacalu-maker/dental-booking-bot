# DentPilot Cloud — сервер лицензий

Отдельная программа (шаг 1 плана — `docs/dentpilot-2/cloud.md`): клиники,
подписки, выдача подписанного файла лицензии, письмо с ним, платежи
переводом, напоминания по датам, журнал. ⛔ Ни одного
импорта из `bot/`; общее с движком — контракт файла и `tests/fixtures/license/`.

```
cd cloud
python -m venv .venv && .venv/bin/pip install -r requirements.txt
python tests/run_tests.py                       # свой прогон, stdlib-харнес
DP_ADMIN_HASH=$(python -m app.tools hash-password) DP_LICENSE_KEY=../tests/fixtures/license/test-key.json \
  DP_MAIL_OUTBOX=./outbox python -m uvicorn app.main:app --port 8090
```

| Переменная | Что |
|---|---|
| `DP_CLOUD_DB` | путь к базе SQLite (по умолчанию `cloud.db` в текущей папке) |
| `DP_LICENSE_KEY` | приватный ключ выдачи: `.pem` (боевой) или `.json` с числами (тестовый) |
| `DP_LICENSE_KID` | имя ключа для `.pem` (у `.json` лежит внутри) |
| `DP_ADMIN_USER`, `DP_ADMIN_HASH` | администратор; хеш — `python -m app.tools hash-password` |
| `DP_SECRET` | подпись куки сессии; пусто — случайная на процесс (сессии не переживут рестарт) |
| `DP_SECURE_COOKIES` | `1` за TLS (Caddy) |
| `DP_SMTP_HOST/PORT/USER/PASS`, `DP_MAIL_FROM` | почта; без хоста письма ложатся файлами в `DP_MAIL_OUTBOX` |
| `DP_BANK_BENEFICIARY`, `DP_BANK_IBAN`, `DP_BANK_NAME`, `DP_BANK_CODE` | реквизиты в письме о переводе; без них платёж создаётся, письмо не уходит |
| `DP_MAIB_PROJECT_ID`, `DP_MAIB_PROJECT_SECRET`, `DP_MAIB_SIGNATURE_KEY` | проект maib ecommerce (L12): оплата картой по ссылке; пусто — только переводом. `DP_MAIB_BASE_URL` — адрес API, меняют только тесты |
| `DP_TRIAL_MODE`, `DP_TRIAL_NOTIFY` | заявка на пробный (`/proba` и из программы): `auto` — файл сразу, программа включается в момент заявки (боевой режим с 26.09, `cloud.env.example`); `approve` (умолчание кода) — заявка ждёт кнопки в админке; письмо о каждой заявке на `DP_TRIAL_NOTIFY` (пусто = ящик поддержки) |
| `DP_DECLARATION` | подписанный PDF декларации поставщика (закон 195, текст — `docs/site/declaratie-195.html`): вложением в каждое письмо с файлом лицензии; пусто или не PDF — письма без него, `check` предупреждает |
| `DP_GOOGLE_CLIENT_ID`, `DP_GOOGLE_CLIENT_SECRET` | кабинет клиники `/cont` (01.10): OAuth-клиент Google «Web application», redirect URI `DP_BASE_URL/auth/google/callback` (DEPLOY.md § 3); оба пусты — кабинет закрыт, страница говорит об этом словами. `DP_GOOGLE_AUTH_URL`, `DP_GOOGLE_TOKEN_URL` — адреса Google, меняют только тесты |
| `DP_RELEASES_API` | `/descarca` (L15): API последнего выпуска GitHub; меняют только тесты |

**Ежедневная задача** — напоминания по таблице `cloud.md › «Напоминания»`
(счёт за 14 дней, за 3 дня, в день срока, накануне и в день режима чтения).
Запуск раз в сутки из cron с тем же окружением, что у сервера; второй запуск
в тот же день ничего не шлёт. Та же задача — кнопкой в списке клиник.

```
# 06:05 UTC = 09:05 Кишинёв летом; даты в файлах лицензий — UTC
5 6 * * * cd /srv/cloud && set -a && . /srv/dentpilot/cloud.env && set +a && python -m app.jobs daily >> /var/log/dentpilot-jobs.log 2>&1
# в Docker: docker exec dentpilot-cloud python -m app.jobs daily
python -m app.jobs daily --at 2026-10-17T06:00:00Z     # разбор: что ушло бы в этот день
```

**Форма пробного периода (L14)** — `GET /proba`: публичная страница на
румынском (название, IDNO, контакт, e-mail, телефон, согласие с условиями),
на неё ссылается сайт. Второго пробного по той же клинике нет: IDNO (если
назван) и e-mail сверяются со всеми клиниками, повтор получает «уже
зарегистрирована», а не файл. В режиме `approve` клиника появляется в
«Заявках на пробный период» на странице клиник — «Выдать пробный и
отправить» или «Скрыть»; в `auto` файл уходит сразу. О каждой заявке — письмо
на `DP_TRIAL_NOTIFY`. Спам держат скрытое поле, лимит 5 заявок с адреса в
час и галочка согласия; всё — в журнале с адресом.

**Оплата из программы (02.10)** — `POST /v1/pay-link` (Bearer = токен клиники из
файла) → адрес публичной страницы `/plata/<id>` на сутки: выбор срока, IDNO на
месте, карта через maib (если настроен) или нота переводом — та же нота, что у
админки и кабинета. Программа открывает адрес в браузере (кнопка «Plătește acum»,
с 1.36.1). Разбор — cloud.md › «Оплата из программы».

**Активация без файла (26.09)** — `POST /v1/trial`: та же заявка из
программы, JSON. Правила те же (`trial.clean`, одна клиника на IDNO/e-mail,
лимит с адреса), клиника заводится с `origin = program` и ждёт в том же
списке заявок с меткой «программа». Новой клинике сервер сразу отдаёт её
токен и адрес `/v1/license`; программа спрашивает по нему раз в минуту и
активируется сама, как только файл выдан (`auto` — сразу, `approve` —
кнопкой «Выдать»), дальше — обычное автообновление. Повтор — законный
случай нового ПК той же клиники: 409 с `verify_id`, а на ящик, записанный у
клиники, уходит код из 6 цифр (L17). `POST /v1/verify {verify_id, code}`
меняет верный код на токен клиники — программа забирает её последний файл.
Код одноразовый, живёт 15 минут, 5 ошибок сжигают его; кодов клинике — не
больше 3 в час, проверок с адреса — 20; в базе только sha256
(`activation_codes`). Если письмо с кодом не ушло — 409 без `verify_id`, со
словами «активируйте файлом из письма». «Скрыть» отзывает токен, и
программа получает 401. Без `DP_BASE_URL` на https оба входа отвечают 503:
файл без `renew` программа сама не заберёт.

**Файл лицензии клинике не показывается (02.10, решение Олега: клиник без
интернета нет).** Файл — механизм программа ↔ сервер и инструмент поддержки
в админке (ссылки в карточке); письма, кабинет и форма `/proba` говорят про
срок и «programul preia singur», вложение письма — только декларация.

**Кабинет клиники (шаг 3, 01.10)** — `GET /cont`: вход через Google
(`/auth/google` → Google → `/auth/google/callback`), страницы по-румынски,
своя кука `dp_cont` на неделю. Клиника с тем же подтверждённым ящиком, что у
аккаунта Google, привязывается сразу — так входит и клиника, заведённая в
админке или из программы; без клиники — регистрация: та же заявка на
пробный, что `/proba` (одна клиника на IDNO/e-mail, лимит с адреса, галочка
условий), e-mail из Google. В кабинете: состояние лицензии словами,
`license.json` (тот же текст, что в админке), кнопка «Descarcă DentPilot»
(`/descarca`), нота на абонемент (месяц или год, перевод или карта maib;
второй открытой ноты нет), реквизиты клиники (e-mail не правится — по нему
привязан вход), выход. Входит обычно директор личным Gmail (Олег 01.10), а
клиника могла быть заведена с другим ящиком: повтор по IDNO при регистрации
— код на ящик клиники (тот же `activation_codes`, что у программы на новом
компьютере), верный код привязывает аккаунт — так же подключается второй
человек клиники; ящика нет или лимит — 409 словами. Олегу письмо «ПОВТОР
из кабинета». В админке карточка клиники показывает
записи кабинета и кнопку «Отвязать» (смена директора: клинике новый e-mail,
старую запись отвязать — новый вход привяжется по ящику). Подпись id_token
не проверяется намеренно: токен приходит прямым HTTPS-запросом сервера к
Google с client_secret (`app/account.py`). Паролей клиник на сервере нет.

**Флот (шаг 3, 02.10)** — `GET /admin/fleet` и JSON `GET /admin/api/fleet`
(кука админа; без неё 401): компьютеры клиник, как они назвались серверу
заголовками `X-DentPilot-Device` (личность машины из `device.json`
программы), `X-DentPilot-Channel`, `X-DentPilot-OS` и версией в `User-Agent`
при суточном запросе файла, заявке и коде (`app/fleet.py`, таблица
`devices`). Кто отстал от последнего выпуска GitHub, кто молчит дольше
недели; раздел «Компьютеры» в карточке клиники, «Calculatoare» в кабинете.
Сервер только слушает — обновиться программе не велит. JSON — тот же отчёт,
что рисует страница: фундамент будущего интерфейса админки.

**Скачивание с сайта (L15, 01.10)** — `GET /descarca`: 302 на
`DentPilot-Setup-X.Y.Z.zip` последнего выпуска из GitHub Releases (ответ API
помнится 10 минут; API молчит — 302 на страницу выпусков), строка
`download` в журнале с адресом. Кнопка `docs/site/descarca*.html` ведёт
сюда — номер версии на сайте не живёт.

**Оплата картой (L12)** — платёж с ссылкой maib: в карточке «Создать платёж»
с выбором «картой» (или «Ссылка на карту» у ожидающего перевода), письмо несёт
ссылку на hosted-страницу maib и, если есть реквизиты, перевод с тем же
reference — долг один. После оплаты maib зовёт
`POST /v1/maib/callback`; подпись проверяется, и всё равно статус
спрашивается у maib (`pay-info`) — только его `OK` продлевает срок и выдаёт
файл, второй callback ничего не делает. Тот же вопрос задают кнопка
«Проверить» и ежедневная задача — callback не обязан дойти. Статус не OK —
платёж остаётся в ожидании со словами maib в карточке; «Новая ссылка» даёт
новую попытку на тот же reference. Страницы возврата — `/pay/ok`, `/pay/fail`.
⚠️ Имена методов maib — по их документации на 25.09, сверить в песочнице
(`app/maib.py`).

**Автообновление файла (L13)** — в каждый выданный файл едет `renew`: адрес
`DP_BASE_URL/v1/license` и токен клиники (рождается с первой выдачей, дальше
один и тот же). Программа клиники раз в сутки делает `GET /v1/license?seq=N`
с `Authorization: Bearer <токен>`: 200 — файл новее `N` (тот же текст, что
скачивается), 204 — новее нет, 401 — токен не признан. След запроса — в
карточке клиники («программа спрашивала … файл у программы»), выдача файла
программе — строкой `renew` в журнале. Поле пишется только при `DP_BASE_URL`
на https (или loopback для стенда): `python -m app.tools check` говорит, что
есть.

**Боевой ключ** делается один раз на сервере и никогда не покидает его:

```
python -m app.tools keygen --kid 2026a --out /srv/dentpilot/keys/2026a.pem
```

Команда печатает строку для таблицы `KEYS` в `bot/app/core/rsa_verify.py` —
её и только её кладут в программу. До этого шага лицензия в программе не
применяется вовсе (`license.applies()`). ✅ Ключ `2026a` в программе с
1.36.0 (02.10.2026); строку повторно печатает `python -m app.tools pubkey`.
