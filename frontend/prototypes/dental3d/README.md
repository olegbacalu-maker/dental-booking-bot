# Dental3D — технический прототип

Один зуб, пять поверхностей, наведение, клик, состояние React. **Ничего
больше.** Ни одонтограммы, ни диагнозов, ни плана лечения, ни пациента, ни
обращений к API, ни сохранения.

```powershell
npm run dev:dental3d
```

---

## Что именно проверялось

| Вопрос | Ответ |
|---|---|
| Можно ли отделить 5 поверхностей на одном меше? | да, группами геометрии |
| Можно ли по клику узнать поверхность? | да, `faceIndex` → группа, без знания геометрии в UI |
| Нужен ли постоянный animation loop? | нет, кадры по требованию |
| Переживает ли сцена unmount без утечки контекста? | да, 21 монтирование → 0 висящих контекстов |
| Добавляет ли прототип мигание? | нет: контейнер фиксирован, кадров в покое 0 |

## Устройство

```
surfaces.ts           словарь пяти поверхностей (буквы движка M/O/D/V/L)
toothGeometry.ts      процедурная геометрия моляра 16 + разбиение на группы
scene.ts              сцена three.js: камера, свет, орбита, пикинг, dispose
Dental3DViewer.tsx    React-обёртка: жизненный цикл и ресайз
Dental3DPrototype.tsx экран: состояние React, панель, controls
dental3d.css          оформление, переменные темы движка с запасными значениями
index.html + main.tsx отдельная dev-страница (в сборку не входит)
```

Деление ответственности жёсткое: **React не рисует 3D**. Дерево компонента
статично, подсветка поверхности — императивное присваивание в уже созданную
сцену. Поэтому движение мыши не запускает reconciliation.

## Модель зуба

Процедурная, ноль байт ассетов, ноль чужих лицензий.

* Коронка — суперэллипс в поперечнике, профиль по высоте задан сплайном
  Catmull-Rom (шейка сужена, экватор в нижней трети).
* Жевательная площадка — четыре бугра гауссианами, центральная ямка и две
  борозды вычитанием, краевой гребень общий со стенкой.
* Три корня (медиально-щёчный, дистально-щёчный, нёбный) — отдельная
  геометрия, в пикинге не участвует.

Размеры взяты средние для 16-го зуба: 10 мм мезио-дистально, 11 мм
вестибуло-нёбно, коронка 7,6 мм, корни 11–13 мм. Одна единица сцены = 1 мм.

**Почему не GLB.** `vite.config.ts` объявляет `assetFileNames`, который
бросает исключение на любой ассет кроме `.css`: маршрут движка
`/static/{kind}/{name}` пропускает только css, js и fonts. Любой `.glb`,
импортированный через Vite, уронил бы `npm run build`. Плюс сторонняя
dental-модель — это чужая лицензия внутри медицинского продукта.

## Разделение поверхностей

Геометрия коронки — **один** `BufferGeometry` с пятью группами. Треугольник
попадает в группу при генерации, а не подбором постфактум:

* вся жевательная площадка → `occlusal`;
* стенка делится по углу θ (отсчёт от +x = дистально к +z = вестибулярно):
  дистальная −30°…30°, вестибулярная 30°…150°, медиальная 150°…210°,
  нёбная 210°…330°. Проксимальные поверхности уже: 60° против 120°.

Индексы сшиваются подряд по группам, поэтому `faceIndex` → номер группы —
это один просмотр в `Uint8Array faceSurface`. Нормали считаются по ВСЕЙ
геометрии до разрезания, поэтому швов на границах секторов нет.

Пять групп = пять материалов у одного меша. Подсветка — присваивание цвета
материалу, без перестройки сцены и без новых draw call'ов.

## Пикинг

`pointermove` → не чаще одного кадра (`requestAnimationFrame`) → луч
`THREE.Raycaster` по коронке → `faceIndex` → `faceSurface[faceIndex]` →
`SURFACE_ORDER[slot]`. Колбэк в React вызывается **только при смене**
поверхности.

Клик отличается от вращения камеры: если между `pointerdown` и `pointerup`
курсор сместился больше чем на 4 px, это было вращение и выбор не меняется.

## Состояние React

```ts
{ tooth: 16, selectedSurface: 'occlusal' | 'buccal' | 'lingual' | 'mesial' | 'distal' | null }
```

Наведение — отдельный `useState` рядом (оно не часть клинической записи).
Повторный клик по выбранной поверхности снимает выбор.

## Имена поверхностей

`surfaces.ts` заранее использует буквы движка DentPilot
(`Odontogram.surfaces`, `ToothInfo.sf`, цели `data-s` серверного SVG):

| id | буква данных | на экране | румынское имя |
|---|---|---|---|
| `occlusal` | `O` | O | ocluzal |
| `buccal` | `V` | V | vestibular |
| `lingual` | `L` | **P** | palatinal |
| `mesial` | `M` | M | mezial |
| `distal` | `D` | D | distal |

У верхней челюсти язычная поверхность показывается как нёбная («P»), ключ
данных остаётся «L» — то же правило, что в `src/features/clinical/chart.ts`,
функция `surfaceLetter()`. Второго словаря поверхностей в клиенте нет и не
будет.

## Производительность и мигание

* **Кадров в покое — ноль.** Постоянного цикла нет: кадр заказывает
  `invalidate()`, его зовут орбита, наведение и ресайз. Инерция камеры
  поддерживает себя сама и гаснет вместе с движением.
* **Контейнер холста фиксирован** (`height: 560px`), `contain: paint`, ни
  одного `transition`. Размер не может измениться во время взаимодействия,
  поэтому `ResizeObserver` молчит, а WebGL не пересоздаёт буферы.
* **devicePixelRatio ограничен 2** и перечитывается только на ресайзе.
* `renderer.setSize(w, h, false)` — размер холста задаёт CSS; иначе three
  вписал бы свои px в стиль и контейнер прыгал бы на каждом ресайзе.
* `dispose()` снимает слушатели и `ResizeObserver`, освобождает геометрии,
  материалы, окружение и рендерер, зовёт `forceContextLoss()` и убирает
  холст. В dev StrictMode монтирует компонент дважды — первый контекст
  отпускается, живым остаётся один.

## Что НЕ сделано намеренно

на сервер, React Three Fiber (см. комментарий в начале `scene.ts` — конфликт
peer-зависимостей с React 19.3), `@react-three/drei`, загрузка внешних
моделей, анимации, текстуры.
