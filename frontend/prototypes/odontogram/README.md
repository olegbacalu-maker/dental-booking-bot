# Odontogram — макет одонтограммы: три раскладки 2D и вид 2D/3D

Два HTML-файла на **зубах движка**, без сборки и без сервера:

- `index.html` — три раскладки 2D: анатомическая дуга (вид сверху обеих
  челюстей), схема поверхностей MODVL (пятизонный квадрат) и нынешняя
  панорама двумя рядами;
- `3d.html` — обе челюсти в 3D (three.js) и та же карта 2D под ними, на
  одних данных: клик по поверхности в любом из видов меняет состояние.

Нужны, чтобы выбрать раскладку и оценить 3D глазами на одном примере
пациента — до того, как что-то менять в `src/features/clinical/`.

## Открыть

- двойным щелчком по файлу (шрифт Inter и three.js подтягиваются из сети,
  без сети 2D работает на системном шрифте, 3D не загрузится и скажет об
  этом);
- или из `frontend/`: `npm run dev:odontogram` и `npm run dev:odontogram3d`.

2D: клик по зубу выбирает его, клик по поверхности переключает «— → carie →
obturație → —», в инспекторе справа меняются состояние зуба, отметка
«în tratament» и поверхности; стрелки — соседний зуб.

3D: перетаскивание — вращение, колёсико и щипок — зум, клик по поверхности
коронки — та же смена состояния. Кнопки видов: Frontal, Ocluzal sus/jos
(вторая челюсть прячется сама, иначе она закрывает обзор), Dreapta, Stânga;
переключатели: Rădăcini (десна прозрачная — видны корни и имплант), Numere,
Maxilar, Mandibular. Ссылки вида `3d.html#3d-jos-xray` открывают нужный вид.
Тёмная тема — от системы.

## Пересобрать

```powershell
python frontend\prototypes\odontogram\gen.py        # index.html
python frontend\prototypes\odontogram\gen.py --3d   # 3d.html
```

Скрипт импортирует `bot/app/teeth_svg.py` (у него нет импортов проекта,
fastapi не нужен) и выгружает контуры коронок, корней, фиссур, долек, зоны
поверхностей и палитру состояний как данные. HTML — результат, руками его
не править: правится `gen.py`.

## Откуда 3D

- Размеры зубов — из движка: мезио-дистальная и вестибуло-язычная ширина
  берутся из вида сверху (`occ_half`, 1 единица = 0,289 мм), число корней —
  из `root_count`. Высота коронки и длина корней — таблицы по классам зуба.
- Форма — по методу прототипа `dental3d`: суперэллипс в поперечнике, профиль
  по высоте сплайном Catmull-Rom, бугры гауссианами, борозды вычитанием;
  резец сужается к режущему краю, клык — к вершине. Корни — эллиптические
  конусы с дистальным наклоном. Ни одной сторонней модели, ноль ассетов.
- Раскладка — та же парабола, что в 2D-дуге: сумма ширин зубов растягивает
  дугу, зуб стоит щёчной стороной наружу, мезиальной к средней линии
  (отражение квадрантов 2 и 4 через базис с отрицательным определителем).
- Цвета состояний те же, что в 2D: поверхность с кариесом краснеет, с
  пломбой синеет, коронка золотая, имплант — титановый винт с фиолетовым
  кольцом, удалённый — лунка в десне, отсутствующий — полупрозрачный
  призрак, «în tratament» — зелёное кольцо у шейки.
- three.js — UMD-сборка r158 с cdn.jsdelivr.net (последняя версия с
  `build/three.min.js`; артефакты claude.ai пускают скрипты только с
  cdnjs, jsdelivr и unpkg). В программе тот же движок стоит в
  `node_modules` (`three` ^0.180), а прототип `dental3d` уже держит сцену,
  пикинг и жизненный цикл React — 3D в программу пойдёт оттуда.

## Что здесь нарочно НЕ так, как в программе

- На странице есть JS-порт правил отрисовки состояния (`frontal()`,
  `occlusal()`) — иначе поверхности не переключались бы без сервера. Это
  второй движок, и в `src/` ему хода нет (контракт
  `docs/dentpilot-2/clinical-chart.md`): в программе рисунок зуба отдаёт
  сервер, клиенту остаётся композиция — расстановка и поворот готовых SVG.
- Пример пациента вшит в страницу (`SAMPLE`), правки никуда не сохраняются,
  «Resetează exemplul» возвращает исходное.
- Молочного ряда, пародонта, истории и заметок зуба нет.
- Цвета интерфейса — токены дизайн-системы Dental3D (светлая и тёмная тема);
  в программе их место займут переменные `core/theme.py`. Цвета состояний —
  движка, без изменений.
